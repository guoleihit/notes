# 判分协议（Grader）

> 供学习教练在「提交答案」后严格执行；教练也可以把本文件作为提示词交给 `general` 子代理做独立复核。
> 原则：**只按答案文件判分，不按印象、不按努力程度加分。**

## 1. 输入

| 输入 | 来源 |
| --- | --- |
| 周次 N | `harness/progress.md` 的 `current_week` |
| 题目 | `每周测试/第NN周-测试.md` 或 `每周测试/模拟考试.md` |
| 标准答案 | `每周测试/答案/第NN周-答案.md` 或 `每周测试/答案/模拟考试-答案.md` |
| 学员作答 | 用户本轮消息 |

## 2. 作答归一化

接受这些写法（大小写不敏感）：

- `1A 2B 3C`、`1.A 2.B`、`1-A`、`1：A`、`1、A`
- 多选题：`9ABC`、`9 A B C`、`9.A,B,C`、`9：ABC`，均视为集合 `{A,B,C}`
- `不会`、`跳过`、`?`、留空 → 记为**未作答**，按错误计

处理规则：

1. 多选题**顺序无关**，按集合比较。
2. 同一题出现多次 → 若答案一致则采用；不一致则**先问学员以哪个为准**，不要自行猜测。
3. 超出题号的作答 → 忽略，并在结果里提示「多答已忽略」。
4. 缺号 → 未作答，按错误计。
5. 学员用「1-5 ABCDA」这类压缩写法 → 请其展开后判分。

## 3. 判分规则

| 题型 | 规则 |
| --- | --- |
| 单选 | 完全一致才得分 |
| 多选 | **全对才得分**；少选、多选、错选均不得分（与考试一致） |

**计算**：

```
得分 = 答对题数
正确率 = 得分 ÷ 总题数 × 100%，保留 1 位小数
通过线 = ceil(总题数 × 0.8)
```

各套卷的通过线（已核对）：

| 试卷 | 总题数 | 通过线 |
| --- | --- | --- |
| 第 01–03 周 | 12 | 10 |
| 第 04–08 周 | 14 | 12 |
| 第 09–10 周 | 16 | 13 |
| 模拟考试 | 40 | 32 |

> 不要用「错几题以内」倒推，直接用上表，避免四舍五入争议。

## 4. 错题归因

每道错题必须给出：

1. **你的答案 / 正确答案**
2. **考点**：一句话说明这题考什么
3. **回读位置**：资料文件名 + 小节号（从答案文件的解析里提取；解析没写就由教练按目录补）

常见归因标签（便于统计薄弱点）：

| 标签 | 对应内容 |
| --- | --- |
| 数字/默认值 | 端口号、计时器、阈值、比例 |
| 分类/清单 | 五趋势、七因素、九设备、十策略 |
| 对比/辨析 | 监管 vs 整形、确认 vs 控制、eBGP vs iBGP |
| 流程/顺序 | 维修后检查、BGP 状态机、PXE 引导 |
| 命令/工具 | ipmitool、sas2ircu、hpssacli、journalctl |
| 概念理解 | 全三层、VRF/RT、MPLS 标签 |

## 5. 输出模板（严格按此结构）

```md
## 判分结果

**得分：11 / 14（78.6%）**
**结论：未通过**（通过线 80%，需 ≥ 12 题）

### 错题明细

| 题号 | 你的答案 | 正确答案 | 考点 | 回读 |
| --- | --- | --- | --- | --- |
| 4 | B | C | 基线用途：维修后检测比对型号 | `02-服务器硬件维修一.md` §2.3 |
| 9 | AB | ABC | 停机维修部件清单 | `03-服务器硬件维修二.md` §1.2 |

### 薄弱点

1. **部件分类**：把「风扇」当成可不停机更换，需重看「盘和电」口诀。
2. **基线场景**：混淆工厂检测与维修后检测的目的。

### 下一步

- 回读上述两节（约 15 分钟），然后说「重测」再做一遍本周卷。
- 本周不进入下一周。
```

通过时把「结论」改成 `通过`，并把「下一步」换成：

```md
- 本周已达标。是否进入第 N+1 周？回复「进入下一周」或「先复习」。
```

## 6. 边界情况

| 情况 | 处理 |
| --- | --- |
| 学员问「这题答案是什么」但还没交卷 | 拒绝给答案，只给提示：「回看资料 §x」 |
| 学员只交了部分题 | 按已交的判，缺号算错；提醒下次一次性提交 |
| 学员要求「算对一点」 | 拒绝，说明多选全对才得分是考试规则 |
| 学员对某题判分有异议 | 先复述标准答案与解析；仍有异议时，把本文件 + 题目 + 答案 + 学员作答交给 `general` 子代理独立复核，以复核一致结论为准 |
| 题目/答案文件缺失 | 停止判分，报告缺失路径，不要凭记忆补题 |
| 同一周多次测试 | 每次都记录；「最佳周测」取最高分 |

## 7. 记录要求

判分完成后，教练必须把结果写入 `harness/progress.md`：

- `周测记录` 表追加一行：`# | 日期 | 得分/总数 | 正确率 | 通过/未通过 | 主要错题（题号+一句考点）`
- 更新该周「周测最佳」与总览行
- 通过 → `week_status: passed`
- 未通过 → `week_status: needs_review`
- 更新 frontmatter 的 `last_score`、`last_rate`、`updated`

**历史记录只追加、不删除。**
