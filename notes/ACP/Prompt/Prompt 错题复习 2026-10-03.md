## 1. temperature 参数的正确说法

**题干：** 你在调用通义千问 API 时设置了 temperature（温度）参数，以下哪种说法是正确的？

A. 温度参数越高，越适合撰写技术报告、代码等有较高确定性需求的场景  
B. 温度参数越高，候选 Token 的概率值之间的差距会变大，从而带来更高的随机性  
C. 温度参数越高，候选 Token 的概率值会越接近，从而带来更高的随机性  
D. 温度参数越高，低概率的候选 Token 有概率超过高概率的候选 Token

**答案：C**

**逐项解析：**

- **A 错**：温度越高，输出越随机，不适合技术报告、代码等高确定性场景。
    
- **B 错**：温度越高，概率分布会变平缓，候选 Token 的概率差距会变小，不是变大。
    
- **C 对**：温度越高，高概率和低概率 Token 的概率值越接近，随机性更高。
    
- **D 错**：低概率 Token 的概率会提升，但通常不会“超过”高概率 Token；这不是 temperature 作用的准确表述。

## 2. 英文到中文翻译的 user_query

**题干：** 以下哪些 user_query 的设计能够有效引导大模型进行英文到中文的翻译？

A. English to Chinese: "Hello, world!"  
B. 我想知道 "Hello, world!" 用中文怎么说  
C. 把 "Hello, world" 翻译成中文  
D. "Hello,world!" 中文  
E. 将以下内容翻译为中文："Hello, world!"  
F. Translate the following English text to Chinese: "Hello, world!"

**答案：A、B、C、E、F**

**逐项解析：**

- **A 对**：明确指定源语言 English 和目标语言 Chinese。
    
- **B 对**：“用中文怎么说”清楚表达翻译意图。
    
- **C 对**：直接说“翻译成中文”，指令明确。
    
- **D 错**：只写“中文”，过于简略，可能是翻译、解释、查询含义，意图不明确。
    
- **E 对**：明确“翻译为中文”。
    
- **F 对**：英文明确“Translate English text to Chinese”。

## 3. 润色“小猫玩毛线球”可补充哪些说明

**题干：** user_query=“请帮我润色一下如下文段，让文字优美适合朗读：小猫玩毛线球。”为了让大模型更好地理解需求，可以补充哪些说明到 user_query 中？

A. 尽量保持原文的核心意思不变  
B. 将文字翻译成英文  
C. 希望润色后的文字更加生动活泼有趣  
D. 请使用比喻和拟人的修辞手法  
E. 把这段文字扩展成一个 500 字左右的小故事  
F. 目标读者是小学三年级的学生

**答案：A、C、D、F**

> 说明：如果按“可补充的可选增强项”理解，选 **A、C、D、F**。  
> 如果严格理解为“原 query 已直接要求、不新增额外约束”，则核心为 **A、C**。D、F 属于合理可选补充，但不是原 query 必需。

**逐项解析：**

- **A 对**：润色通常应保持原意，补充后能避免模型改写偏离。
    
- **B 错**：翻译成英文与“润色中文文段”的任务冲突。
    
- **C 对**：具体化“优美适合朗读”的风格方向。
    
- **D 对**：可作为实现“优美、生动”的可选修辞要求；但原 query 没强制要求。
    
- **E 错**：扩展成 500 字小故事属于扩写/改写，会改变原任务范围。
    
- **F 对**：可帮助控制用词难度、语气和朗读节奏；但原 query 没强制要求。

## 5. 从客户邮件提取结构化数据

**题干：** 你需要大模型从客户邮件中提取结构性数据（如姓名、订单号、问题类型），以下哪两个选项有助于你达成这一目标？

A. 提供你期望的 JSON 结构示例  
B. 在任务目标中明确“输出 JSON 格式”  
C. 调低温度参数（Temperature）以降低随机性  
D. 要求模型分两步操作：先总结邮件内容，再提取字段

**答案：A、B**

**逐项解析：**

- **A 对**：提供 JSON 结构示例，能明确字段名、字段含义和嵌套结构，提升结构化输出稳定性。

- **C 错**：调低 temperature 可降低随机性，但不是解决“结构化提取”和“格式可控”的核心手段。
    
- **D 错**：先总结再提取可能引入信息丢失或额外错误，通常不如直接提取并约束格式。

## 6. top_p 参数的作用

**题干：** 在控制大模型生成内容的随机性时，top_p 参数的作用是什么？

A. 调整候选 Token 的概率分布  
B. 筛选出累积概率达到阈值的候选 Token  
C. 增加候选 Token 的数量  
D. 减少候选 Token 的数量

**答案：B**

**逐项解析：**

- **A 错**：调整概率分布形状主要是 temperature 的作用。
    
- **B 对**：top_p 将候选 Token 按概率从高到低排序，累加概率，达到阈值后只保留这批 Token。
    
- **C 错**：不是直接增加候选数量；top_p 越低，候选集合通常越小。
    
- **D 错**：不是直接减少候选数量；它是按累积概率动态筛选。

# 补充知识点：temperature 与 top_p

## temperature 与 top_p 的区别和联系

- **temperature**：调整整个概率分布的形状。温度越高，分布越平缓，输出越随机；温度越低，分布越尖锐，输出越确定。
    
- **top_p**：从概率分布中筛选候选 Token 集合。按概率从高到低累加，达到阈值后只保留这批 Token，再从中采样。
    
- **联系**：两者都属于采样策略，都影响随机性和多样性，通常配合使用。
    
- **一般顺序**：`logits → temperature 缩放 → softmax → top_p 截断 → 采样`
    

|对比项|temperature|top_p|
|---|---|---|
|作用方式|调整概率分布形状|截断候选 Token 集合|
|低值效果|输出更确定|候选池更小，输出更确定|
|高值效果|输出更随机|候选池更大，输出更随机|
|极端情况|T→0 近似贪心|p→0 只留极少数 Token|

## top_p 多少会产生多样性和随机性？

- 想要明显多样性和随机性，通常设置 **top_p = 0.9 ~ 1.0**。
    
- 常用：**top_p = 0.95** 左右。
    
- 同时需要配合较高的 temperature，例如 0.7 ~ 1.0。
    
- 如果 `temperature=0`，top_p 再高也几乎不会随机。
    
- 如果只调高 top_p，而 temperature 很低，随机性也不会明显增加。

# 重点记忆清单

- **temperature**：调概率分布形状；越高越随机。
    
- **top_p**：按累积概率筛候选 Token；越低越确定，越高越多样。
    
- **高确定性任务**：低 temperature，低 top_p。
    
- **创意多样任务**：较高 temperature，top_p 约 0.9~0.95。
    
- **任务目标 Object**：做什么，如翻译、分析、生成。
    
- **输出格式**：JSON、HTML、表格等；不要和任务目标混淆。
    
- **注意事项**：包括知识来源、安全拒答、输出范围等约束。
    
- **Few-shot 适用**：数据少、快速适应、原型、创造性写作。
    
- **Few-shot 不适用**：需要深度专业知识的任务。
    
- **Zero-shot 主要靠**：预训练。
    
- **CoT 最适合**：多步推理、逻辑、编程、复杂决策；情感分析不最直接。
