## 第32题

### 题目

如果你的业务流程比较复杂，可以借助百炼上的哪些工具来构建更强大的应用？

A. 可视化工作流  
B. 智能体编排  
C. LlamaIndex 组件  
D. 自然语言处理模型

### 正确答案

**A、B**

### 选项解析

- **A 可视化工作流（正确）**：百炼工作流通过可视化节点编排，把多步骤任务串成稳定、可控、可复现的执行链路，适合复杂固定流程。
    
- **B 智能体编排（正确）**：智能体可自主决策、调用工具，并可与工作流相互嵌套，适合处理需要灵活判断的复杂业务。
    
- **C LlamaIndex 组件（错误）**：LlamaIndex 是可集成/兼容的外部开发框架，不是百炼平台内置的复杂业务流程编排工具。
    
- **D 自然语言处理模型（错误）**：大模型是底层能力，不是用来搭建业务流程结构的编排工具。
    

### 背后知识点

- **工作流**适合确定性高、步骤固定的流程。
    
- **智能体**适合需要自主决策、工具调用、多步推理的场景。
    
- 复杂应用常采用：**工作流 + 智能体嵌套**。
    

### 总结

复杂业务流程应优先考虑：**可视化工作流固化确定性步骤，智能体编排处理灵活决策环节。**

### 扩展

实际架构中可组合：

- 工作流负责审批、订单处理、报告生成等固定链路；
    
- 智能体负责意图理解、工具选择、异常处理；
    
- 外部框架如 LlamaIndex 可在代码层辅助 RAG/检索，但不是本题的流程编排答案。

## 第34题

### 题目

在以下代码片段中，哪些参数可以影响生成文本的多样性？

A. temperature  
B. max_tokens  
C. presence_penalty  
D. seed

### 正确答案

**A、C**

### 选项解析

- **A temperature（正确）**：控制采样随机性。温度越高，输出越多样、更有创造性；温度越低，越确定。
    
- **B max_tokens（错误）**：只限制生成的最大 Token 数量，即回答长度上限，不直接改变词汇选择概率分布。
    
- **C presence_penalty（正确）**：惩罚已出现过的词，鼓励引入新词、新话题，提升用词多样性，减少重复。
    
- **D seed（错误）**：控制随机种子，主要影响可复现性。固定 seed 提升可复现性；不固定 seed 只是产生不可复现的随机变化，不等于“调高了多样性”。
    

### 背后知识点

影响多样性的常见参数：

- `temperature`
    
- `top_p`
    
- `presence_penalty`
    
- `frequency_penalty`
    

不影响多样性本身：

- `max_tokens`：管长度；
    
- `seed`：管可复现性。
    

### 总结

**提升多样性：调高 temperature、调高 presence_penalty。**  
**max_tokens 管长度，seed 管复现。**

### 扩展

易错辨析：

- **重复 ≠ 确定性**：降低 presence_penalty 可能让内容更重复，但不等于输出更确定。
    
- **去掉 seed ≠ 增加多样性**：只是放弃可复现性，不代表模型被调得更多样。

## 第35题

### 题目

在以下代码片段中，哪些操作有助于生成更具确定性的文本？

A. 降低 temperature 值  
B. 减少 max_tokens 值  
C. 降低 presence_penalty 值  
D. 固定 seed 值

### 正确答案

**A、D**

### 选项解析

- **A 降低 temperature（正确）**：温度越低，模型越倾向选择高概率词，输出更稳定；趋近 0 时接近贪心解码。
    
- **B 减少 max_tokens（错误）**：只限制生成长度，不改变采样随机性。
    
- **C 降低 presence_penalty（错误）**：改变的是重复/用词倾向，不是直接提升确定性。
    
- **D 固定 seed（正确）**：相同输入和参数下更容易复现相同或相近输出，提升可重复性和确定性。
    

### 背后知识点

- **确定性**：相同输入、相同参数下输出是否稳定、可复现。
    
- **重复**：内容层面相同词句反复出现。
    
- **可复现性**：固定 seed 的主要作用。
    

### 总结

要提升确定性：

- **降低 temperature**；
    
- **固定 seed**；
    
- 必要时配合 `top_p` 等采样参数。
    

### 扩展

“重复”和“确定性”不是一回事：

- presence_penalty 低可能更重复，但采样仍可能随机；
    
- 固定 seed 提升可复现性，但不等于让内容不重复；
    
- 去掉 seed 只是放弃可复现性，不是增加多样性。

## 第38题

### 题目

你在开发一个可以自动回答客户问题的客服平台。除了回答产品知识问题外，你希望它还能执行与账户相关的操作（例如实时查询用户订单状态、修改账户绑定的手机号、提交工单或退款申请）。你应该考虑引入什么技术来扩展大模型的能力？

A. RAG（Retrieval Augmented Generation）  
B. Agent（智能体）  
C. 大模型微调  
D. 数据增强

### 正确答案

**B. Agent（智能体）**

### 选项解析

- **A RAG（错误/不完整）**：适合基于知识库回答产品知识问题，但不负责实时查询订单、修改手机号、提交退款等业务操作。
    
- **B Agent（正确）**：可通过工具调用/API/函数调用连接订单系统、账户系统、工单系统，完成多步决策和业务执行。
    
- **C 大模型微调（错误）**：可改善领域话术、格式、分类能力，但不能让模型实时访问业务系统，也不适合直接执行账户操作。
    
- **D 数据增强（错误）**：主要用于扩充训练数据，与实时业务操作无直接关系。
    

### 背后知识点

客服平台常见组合：

- **RAG**：产品知识问答；
    
- **Agent**：意图理解、工具选择、业务操作；
    
- **工具/API**：订单查询、手机号修改、工单提交、退款申请；
    
- **安全机制**：权限校验、二次确认、审计日志。
    

### 总结

“回答知识”靠 RAG，“执行操作”靠 Agent + 工具/API。  
本题问扩展执行能力，选 **Agent**。

### 扩展

智能体不只是工具调用，还包括：

- **规划 Planning**：任务分解、策略选择、动态调整；
    
- **记忆 Memory**：短期上下文、长期偏好、经验记忆；
    
- **反思 Reflection**：自我评估、过程复盘、自我修正；
    
- **多智能体协作 Multi-Agent**：角色分工、通信协调、冲突解决。

## 第42题

### 题目

一家教育科技公司想开发人工智能教学产品。哪些方案能利用AI实现个性化、智能化和普惠教育？

A. 方言识别系统辅助少数民族学生练习普通话  
B. 根据学习进度和学生兴趣生成课后实验，如电路故障排查等  
C. 考试时在线抽取选择题，实时自动判卷，对每个人的错误选项提供标准解析  
D. 自适应学习平台根据学生水平动态调整题库

### 正确答案

**A、B、D**

### 选项解析

- **A 方言识别辅助普通话练习（正确）**：AI 语音识别与发音评测，降低语言学习门槛，体现智能化和普惠教育。
    
- **B 根据进度和兴趣生成实验（正确）**：生成式 AI 个性化生成实验内容，体现个性化和智能化。
    
- **C 在线抽题、自动判卷、标准解析（错误/不够准确）**：偏自动化考试与判卷，“标准解析”通常是统一预设，个性化反馈不足，不能很好体现题目要求。
    
- **D 自适应学习平台动态调整题库（正确）**：根据学生水平调整题目难度和内容，是典型个性化学习路径。
    

### 背后知识点

AI 教育应用方向：

- 语音识别与发音评测；
    
- 生成式个性化内容；
    
- 自适应学习；
    
- 智能辅导与反馈。
    

### 总结

能体现个性化、智能化、普惠教育的是：**A、B、D**。  
C 更偏自动化评测，个性化程度不足。

### 扩展

真正个性化反馈应基于：

- 学生错因分析；
    
- 知识掌握图谱；
    
- 学习风格与兴趣；
    
- 历史学习轨迹；  
    而不是只给出统一“标准解析”。

## 第43题

### 题目

每次把全部对话历史完整发给模型，关于这种做法哪些认识正确？

A. 每轮API调用费用越来越高，因为Token数越来越多  
B. 历史太长时模型可能注意力分散，忽略中间重要信息  
C. 只要没超出上下文窗口限制，保留的历史越多越好  
D. 对话超过上下文长度限制后，早期内容会被截断丢失

### 正确答案

**A、B、D**

### 选项解析

- **A（正确）**：全部历史完整发送会导致输入 Token 随轮次累积，成本和延迟上升。
    
- **B（正确）**：长上下文可能出现“中间信息丢失”或注意力分散，噪声增多，关键信息被淹没。
    
- **C（错误）**：上下文窗口是上限，不是越多越好。历史过多会带来成本、延迟、干扰、矛盾信息等问题。
    
- **D（正确）**：超过上下文长度限制后，早期内容无法完整保留，需要截断、摘要或检索。
    

### 背后知识点

长对话管理策略：

- 滑动窗口；
    
- 对话摘要；
    
- 关键信息提取；
    
- RAG 检索相关历史；
    
- 分层记忆。
    

### 总结

完整发送全部历史：

- 成本累积上升；
    
- 长上下文稀释注意力；
    
- 超限后早期内容丢失；
    
- 不是“没超限就越多越好”。
    

### 扩展

“上下文窗口大”不等于“模型能同等有效利用所有内容”。  
工程上应关注：**相关性、压缩、检索、记忆管理**，而不是无脑堆历史。

## 第58题

### 题目

在提取标签的过程中，以下哪些操作是正确的？

A. 如果某类标签未识别到，则不输出该类  
B. 输出所有标签类型，即使未识别到  
C. 使用JSON格式输出标签  
D. 使用XML格式输出标签

### 正确答案

**A、C**

### 选项解析

- **A（正确）**：识别到什么输出什么，未识别到的不输出，避免空值、冗余和模型硬凑/臆造标签。
    
- **B（错误）**：即使未识别到也输出所有标签类型，容易产生空字段和默认值，增加解析负担，也可能诱导编造。
    
- **C（正确）**：JSON 结构清晰、易解析、易校验，是标签提取和结构化输出的常用推荐格式。
    
- **D（错误/不推荐）**：XML 也是结构化格式，大模型也能生成和理解；但在标签提取、结构化输出、工具调用等场景中，JSON 通常是更通用、更默认的最佳实践。若下游明确要求 XML，则另说。
    

### 背后知识点

结构化输出常用格式：

- **JSON**：平台支持广，解析成熟，适合 JSON Mode / JSON Schema / 工具调用；
    
- **XML**：可用，常用于提示词分隔指令和上下文，但标签提取场景通常不是首选；
    
- **YAML/CSV/Markdown**：特定场景可用，但通用结构化输出不如 JSON。
    

### 总结

标签提取推荐：

- **未识别到的不输出**；
    
- **优先使用 JSON 结构化输出**。
    

### 扩展

易错点：

> “大模型只用 JSON”是错误说法。  
> 更准确：**大模型能理解 XML 等多种格式，但在标签提取和程序化解析场景中，JSON 通常是更推荐的最佳实践。**

# 今日综合总结

## 1. 参数与生成控制

- **temperature 高 → 更多样；低 → 更确定**
    
- **presence_penalty 高 → 减少重复、鼓励新词；低 → 更可能重复**
    
- **max_tokens 只管长度**
    
- **seed 只管可复现性**
    
- **重复 ≠ 确定性；去掉 seed ≠ 增加多样性**
    

## 2. 复杂应用构建

- **工作流**：固定、可控、多步骤流程；
    
- **智能体**：自主决策、工具调用、多步执行；
    
- **RAG**：知识问答；
    
- **Agent + 工具/API**：执行订单查询、账户修改、工单、退款等业务操作；
    
- 智能体还包括：**规划、记忆、反思、多智能体协作**。
    

## 3. 长对话管理

- 全量历史发送会增加成本和延迟；
    
- 长上下文会稀释注意力；
    
- 超限后早期内容会丢失；
    
- 应使用摘要、滑动窗口、关键信息提取、RAG 检索等策略。
    

## 4. 结构化输出

- 标签提取：**未识别不输出 + JSON 优先**；
    
- XML 可用，但通用标签提取场景通常不如 JSON 推荐；
    
- 平台若强制 JSON Schema/JSON Mode，则按平台约束输出 JSON。
    

## 5. 教育 AI

- 个性化、智能化、普惠教育方案：**方言识别辅助普通话、生成个性化实验、自适应学习题库**；
    
- 单纯自动判卷 + 标准解析个性化程度不足。

# 今日高频易错点清单

1. **以为 max_tokens 能影响多样性/确定性**：它只限制长度。
    
2. **以为固定 seed 能提升多样性**：它提升可复现性。
    
3. **以为去掉 seed 就是增加多样性**：只是放弃可复现性。
    
4. **把“重复”当成“确定性”**：二者维度不同。
    
5. **以为 Agent 就是工具调用**：工具调用只是执行手段，Agent 还包括规划、记忆、反思、协作。
    
6. **以为 RAG 能执行业务操作**：RAG 主要增强知识回答，业务操作要靠 Agent/API。
    
7. **以为上下文没超限就越多越好**：长上下文有噪声、成本和注意力问题。
    
8. **以为大模型只能用 JSON**：XML 也能用，但标签提取场景通常 JSON 更推荐。
    
9. **以为未识别标签也要全部输出**：应识别什么输出什么，避免空值和臆造。
    
10. **把自动判卷等同于个性化教育**：统一标准解析不等于个性化反馈。
