## 二、逐题解析

### 148. 检测文档中营销性表达的方法

**题目：** 在检测文档内容中是否存在营销性表达时，下列哪种方法可以更全面地识别问题？  
A. 识别所有内容错误的部分  
B. 让大模型自动修改内容  
C. 逐条单独识别营销词汇  
D. 一次性生成所有类型的识别结果

**答案：D**

**解析：**

- A 错：内容错误不等于营销表达。
    
- B 错：修改不等于识别。
    
- C 有作用但局限：只覆盖词汇层面，容易漏掉隐性营销、句式和语境。
    
- D 相对更全面：可同时覆盖显性营销词、隐性表达、语气、句式等类型。
    

**知识点：** 营销表达检测应综合词汇、句式、语气、语境和隐性营销。  
**扩展：** D 也有遗漏风险。实际工程建议“定义类型清单 → 分类型/分批识别 → 汇总去重 → 规则或人工复核”。

### 151. 自定义 LangChain LLM 对象的核心要素

**题目：** 如果想要自定义 LangChain 的 LLM 对象，理论上只需要准备以下哪个要素？  
A. 一个 API Key  
B. 一个 Model name  
C. 一个 JSON，直接加载即可  
D. 一个输入为字符串，输出为字符串的函数

**答案：D**

**解析：**

- A、B 是调用具体模型服务的参数，不是自定义 LLM 对象的本质。
    
- C 错：JSON 直接加载不是自定义 LLM 的核心。
    
- D 对：核心是实现类似 `_call(prompt: str) -> str` 的字符串输入输出逻辑。
    

**知识点：** LangChain 自定义 LLM 通常继承 `LLM`，实现 `_call` 和 `_llm_type`。  
**扩展：** 可选实现 `_stream` 支持流式、`_acall` 支持异步、`_identifying_params` 输出参数信息。

### 152. 文档审阅中为什么不建议一次输出所有结果

**题目：** 在文档审阅中，为什么不建议一次输出所有的结果？  
A. 只需关注营销表达  
B. 大模型可能会漏掉一些错误  
C. 内容错误不需要处理  
D. 信息量过大，难以理解  
E. 直接提问：“请优先将NSC 翻译为神经干细胞”

**答案：B；若为多选可考虑 B、D**

**解析：**

- A 错：文档审阅不只关注营销表达。
    
- B 对：一次性处理大量、多类型问题时，模型注意力分散，容易漏错。
    
- C 错：内容错误需要处理。
    
- D 部分合理：信息量过大影响理解，但核心原因是模型识别遗漏。
    
- E 错：这是具体指令示例，不是原因。
    

**知识点：** 复杂审阅应分类型、分批次、分步骤处理并复核。  
**扩展：** 单次全量输出受输出长度、注意力分配、类型边界影响，漏检风险更高。

### 155. 不定期文档分析任务的最优计费方式

**题目：** 某企业需要部署一个大模型，不定期自动地分析现有的产品文档，并产出改进建议，以下哪一种计费方式可以在满足业务需求的同时最大化降低运行成本？  
A. 通过按量付费方式创建 GPU 资源  
B. 使用抢占式实例（Spot Instance），同时设计好任务中断的自动恢复机制  
C. 购买显卡并搭建本地服务器  
D. 通过预付费（包年包月）方式创建 GPU 资源

**答案：B**

**解析：**

- A 灵活但单位成本高于 Spot。
    
- B 最省成本：抢占式价格低，配合中断恢复可满足可中断批处理任务。
    
- C 前期投入大、运维成本高。
    
- D 适合长期稳定高负载，不适合不定期任务。
    

**知识点：** 抢占式实例适合无状态、容错、可中断的批处理任务。  
**扩展：** 需设计检查点、重试、任务队列、自动恢复；数据库等有状态高稳定业务不适合。

### 165. 流式对话 `stream_chat(messages)` 适用场景

**题目：** 以下哪些场景适合使用流式对话 `LLM_MODEL.stream_chat(messages)`？  
A. 实时聊天机器人，需要立即响应用户输入。  
B. 需要对大模型的输出进行实时监控和干预的场景。  
C. 用户需要快速获得初步结果，后续可以继续补充信息完善结果。  
D. 只需要一次性返回完整结果的简单任务，例如翻译单个单词。  
E. 需要处理长文本输入的场景，可以逐步返回结果，避免超时。

**答案：严格 A、B、C；宽松 A、B、C、E**

**解析：**

- A 对：实时聊天需要逐段返回，降低等待感。
    
- B 对：流式输出便于实时观察、中断和干预。
    
- C 对：先返回初步结果，再继续完善。
    
- D 错：简单一次性任务流式收益很小。
    
- E 有瑕疵：后半句符合流式输出价值，但“长文本输入”说法不准确。流式主要流的是**输出**，不是输入。更准确应为“长文本生成/输出场景，逐步返回结果，避免整体超时”。
    

**知识点：** `stream_chat` 核心是流式输出。  
**扩展：** 流式适合低延迟交互、长回答生成、可中断/可监控场景；不适合短小一次性任务。考试中要区分“流式输入”和“流式输出”。

### 166. 用户输入清洗和预处理以提高安全性

**题目：** 以下哪些代码片段可以有效地对用户输入进行清洗和预处理，以提高大模型应用的安全性？  
A. 将用户输入中的 emoji 表情符号替换为文本描述。  
B. 将用户输入转换为小写。  
C. 限制用户输入的长度。  
D. 去除用户输入中的 HTML 标签。  
E. 将用户输入中的 URL 替换为特殊的占位符。  
F. 先把英文全部翻译为中文。

**答案：C、D、E**

**解析：**

- C 对：防止超长输入、资源消耗和注入绕过。
    
- D 对：降低 XSS、HTML 注入风险。
    
- E 对：对 URL 做风险隔离，降低恶意链接、自动访问、提示注入载体和敏感信息泄露风险。
    
- A、B 主要是文本规范化，不是核心安全手段。
    
- F 会改变语义，不属于安全清洗。
    

**知识点：** 输入安全清洗包括长度限制、标签过滤、URL 抽象、白名单校验、输出转义等。  
**扩展：** URL 替换不只是防恶意链接，还能防止自动访问不可信地址、SSRF、日志污染和 token 泄露。仅替换 URL 不等于安全，应配合白名单和输出转义。

### 169. 阿里云支持的模型部署平台

**题目：** 阿里云支持的模型部署平台包括？  
A. 云服务器ECS  
B. 函数计算FC  
C. 人工智能平台PAI-EAS  
D. 大模型服务平台百炼  
E. 创建新的 Acsictant

**答案：A、B、C、D、E**

**解析：**

- A 对：ECS/GPU 云服务器可自建模型部署。
    
- B 对：FC 提供 Serverless GPU，可部署大模型推理，但需注意冷启动和超时限制。
    
- C 对：PAI-EAS 是模型在线服务部署平台。
    
- D 对：百炼是全托管大模型服务平台。
    
- E 按 ACS（容器计算服务）理解正确；题干“Acsictant”疑似笔误。
    

**知识点：** 阿里云模型部署覆盖 IaaS（ECS）、Serverless（FC/ACS）、AI 平台（PAI-EAS）、全托管 MaaS（百炼）。  
**扩展：** FC 适合低频、弹性、可容忍冷启动场景；高并发低延迟常驻服务更适合 PAI-EAS 等。

### 170. 百炼平台的主要适用场景

**题目：** 百炼平台的主要适用场景是？  
A. 闭源模型的低成本高并发部署  
B. 边缘计算任务  
C. 长期稳定的私有化服务  
D. 开源模型的本地部署

**答案：A**

**解析：**

- A 对：百炼是全托管 MaaS 平台，免运维、按需调用，支持高并发和成本优化。
    
- B 错：百炼是中心化云托管平台，不是边缘计算平台。
    
- C 不是主要默认场景：百炼专属版可私有化，但不是标准百炼的主要定位。
    
- D 错：百炼核心是云端托管调用，不是本地部署。
    

**知识点：** 百炼聚合通义千问及第三方模型，通过 API 提供托管模型服务。  
**扩展：** 百炼语境下“部署闭源模型”通常指调用平台托管的闭源模型服务，而不是下载权重本地安装。

### 172. 端云协同部署的核心优势

**题目：** 端云协同部署的核心优势是？  
A. 完全免除云端依赖  
B. 平衡计算效率与用户体验  
C. 降低硬件采购成本  
D. 提高数据隐私等级

**答案：B**

**解析：**

- A 错：端云协同仍依赖云端。
    
- B 对：端侧低延迟轻量处理，云端强算力复杂处理，平衡效率和体验。
    
- C 不是核心优势。
    
- D 有部分相关性，但不是最概括的核心优势。
    

**知识点：** 端云协同 = 端侧轻量/低延迟/隐私敏感处理 + 云端大算力/复杂模型处理。  
**扩展：** 典型例子是手机语音助手：唤醒词和简单指令端侧做，复杂语义理解和内容生成云端做。

### 75. ROUGE 分数描述

**题目：** 关于 ROUGE 分数，哪些描述正确？  
A. ROUGE-1 关注单个词的重叠  
B. 仅适用于翻译任务  
C. ROUGE-L 基于最长公共子序列  
D. ROUGE-P 是精确率指标

**答案：A、C、D**

**解析：**

- A 对：ROUGE-1 基于一元词重叠。
    
- B 错：ROUGE 主要用于摘要，也用于文本生成、翻译、问答等。
    
- C 对：ROUGE-L 使用最长公共子序列。
    
- D 对：`-P` 表示 Precision 精确率。
    

**知识点：** ROUGE 衡量生成文本与参考文本的重叠程度，常见有 ROUGE-N、ROUGE-L、ROUGE-P/R/F 等。  
**扩展：** ROUGE 偏重召回和内容覆盖；实际评估常与 BLEU、BERTScore、人工评估结合。

### 181. 使用 Marp 将课程内容转为 PPT 的注意事项

**题目：** 使用 Marp 将课程内容转为 PPT 时，需注意哪些事项？  
A. 避免复杂 Markdown 语法  
B. 统一图片尺寸与排版  
C. 添加自定义主题样式  
D. 确保代码块正确渲染

**答案：A、B、C、D**

**解析：**

- A 对：复杂或不受支持的 Markdown/HTML 可能导致渲染异常。
    
- B 对：统一图片宽度/高度或容器，避免版面混乱。
    
- C 属于值得注意的事项，但**不是必须**。内置主题可满足基本需求；需要品牌视觉或特殊排版时再自定义。
    
- D 对：代码块需指定语言、处理长行溢出和缩进。
    

**知识点：** Marp 基于 Markdown 生成幻灯片，需关注语法兼容、图片适配、主题样式、代码高亮。  
**扩展：** “统一图片尺寸”不是要求像素完全一样，而是视觉规格协调，常用统一宽度、统一高度或 `fit/cover` 容器适配。

### 182. 使用 Marp 创建演示文稿的推荐做法

**题目：** 使用基于 Markdown 的工具 Marp 创建演示文稿时，以下哪些做法是推荐的？

- D 错：注释虽不显示，但可用于源文件维护和协作，不应忽略。
    

**知识点：** Markdown/Marp 的标题、列表缩进、代码块和注释规范。  
**扩展：** 注释不渲染不等于无价值；复杂课程源文件更需要注释维护。

### 188. 评估 SQL 生成任务的语义完整性

**题目：** 下列哪个指标最适合评估 SQL 生成任务的语义完整性？  
A. ROUGE-L  
B. BLEU  
C. Perplexity  
D. mAP

**答案：A**

**解析：**

- A 相对最合适：ROUGE-L 基于最长公共子序列，能反映结构和内容覆盖。
    
- B 偏表面 n-gram 精确率。
    
- C 衡量语言模型困惑度，不直接评估 SQL 语义完整性。
    
- D 用于目标检测/检索排序。
    

**知识点：** SQL 生成理想评估是执行结果等价性。  
**扩展：** 更推荐 Execution Accuracy、Test-Suite Accuracy、AST 归一化比较、LLM Judge、安全 SQL 率、延迟和 Token 消耗等综合评估。ROUGE-L 只是选项中的相对最优。

### 190. 分词化描述

**题目：** 以下关于分词化的描述，哪些是正确的？  
A. 在分词化过程结束后，每个 token 需要转换成一个数字 id  
B. 分词化是自然语言处理中的一个步骤，旨在将文本切分成更小的管理单元  
C. 词粒度分词化适用于英语等西方语言  
D. 每个 token 会被直接用其对应的词汇字符串作为词表中的唯一标识

**答案：A、B、C**

**解析：**

- A 对：token 需映射为词表数字 ID 才能输入模型。
    
- B 对：分词化是 NLP 基础步骤，切分为更小处理单元。
    
- C 对：词粒度依赖空格等词边界，适合英语等西方语言。
    
- D 错：词表中通常以数字 ID 作为模型输入标识，词汇字符串用于映射。
    

**知识点：** 分词化、词表映射、token ID。  
**扩展：** 中文常用字粒度、子词粒度或专门分词；子词算法如 BPE、WordPiece、SentencePiece。

### 192. 适合使用语义切片的场景

**题目：** 以下哪些场景适合使用语义切片？  
A. 文档逻辑性强  
B. 内容专业且结构复杂  
C. 需要严格控制 Token 数量  
D. 处理简单对话文本

**答案：A、B**

**解析：**

- A 对：语义切片可沿章节、段落、主题边界切分，保留逻辑。
    
- B 对：专业复杂文档按语义切分更能保持信息完整。
    
- C 不适合作为首选：语义切片不保证 Token 数严格一致；应使用固定长度/递归切分并设置 chunk size 和 overlap。
    
- D 一般不需要：简单对话按轮次或固定长度切分即可。
    

**知识点：** 语义切片 vs 固定长度切分。  
**扩展：** 语义切片适合长文档、知识库、RAG 高质量切片；但需控制切片大小和重叠，避免过碎或过大。

### 212. 整合视频、音频和字幕时解决同步问题的工具

**题目：** 整合大模型生成的视频、音频和字幕时，哪些工具可帮助解决同步问题？  
A. ffmpeg  
B. moviepy  
C. CosyVoice  
D. Marp

**答案：A、B**

**解析：**

- A 对：FFmpeg 可烧录字幕、调整字幕延迟、音画对齐、重新封装多轨流。
    
- B 对：MoviePy 可按时间轴精确设置字幕和音视频片段的开始/结束时间，合成复合剪辑。
    
- C：CosyVoice 核心是语音合成和音色克隆，不负责多轨时间轴同步。
    
- D：Marp 是 Markdown 转幻灯片工具，本身不处理音视频字幕同步。
    

**知识点：** 音视频同步包括时间轴对齐、字幕延迟调整、音画封装、多轨合成。  
**扩展：** 可用 FFmpeg 的 `-itsoffset`、`subtitles` 滤镜，MoviePy 的 `CompositeVideoClip`、`TextClip` 等；自动字幕同步还可配合 `ffsubsync`。

## 三、易错点总结

1. **流式输出 ≠ 流式输入**：165 题 E 的“长文本输入”表述不严谨。
    
2. **“全面识别”不等于“单次全量输出”**：148 选 D，但实际工程应分类型复核；152 说明单次全量易遗漏。
    
3. **抢占式实例核心是低成本 + 可中断恢复**：适合批处理，不适合数据库等有状态高稳定业务。
    
4. **安全清洗要区分规范化和安全控制**：小写、emoji 替换不是核心安全手段；URL 替换不只是防恶意链接。
    
5. **百炼的“部署闭源模型”是托管调用**，不是下载权重本地部署。
    
6. **端云协同不是替代本地或云端，而是分工平衡**。
    
7. **ROUGE 不是只用于翻译**，核心场景是摘要和文本生成评估。
    
8. **mAP 不是普通单标签分类的核心指标**，更适合目标检测、检索排序、多标签排序。
    
9. **分类中的召回率用于关注漏检**，不是查询任务专属。
    
10. **Marp 自定义主题不是必须的**，但属于值得注意的排版事项。
    
11. **FFmpeg/MoviePy 不做图像识别**，图像识别需额外模型或工具。
    
12. **异步审核核心是提交任务 + 轮询/回调获取结果**，不是实时返回或生成波形图。
