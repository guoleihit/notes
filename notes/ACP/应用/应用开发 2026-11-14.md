## 第77题：大模型应用核心监控指标

### 题干

开发者在部署大模型应用时，需监控应用的运行状态。以下哪些指标属于核心监控指标？

### 选项

- A. 推理延迟：从请求发出到接收响应的时间
    
- B. 并发量（QPS）：单位时间内的请求次数
    
- C. 准确率：模型回答与正确结果的匹配程度
    
- D. 显存占用：模型运行时消耗的 GPU 显存大小
    

### 答案

**A、B、D**

### 逐项解析

- **A 推理延迟：正确。**  
    延迟直接影响用户体验和系统响应能力，是运行状态监控的核心指标。实际还应关注 P95/P99 分位数，而不是只看平均值。
    
- **B 并发量（QPS）：正确。**  
    QPS/RPM 反映系统负载和吞吐能力，是容量评估、限流、扩容和告警的基础指标。
    
- **C 准确率：不选为“核心运行指标”。**  
    准确率很重要，但它属于**质量评估/业务效果监控**，通常依赖离线评测、抽样评估、人工或 LLM-as-Judge，不是实时运行状态监控的核心指标。
    
- **D 显存占用：正确。**  
    大模型推理的 KV Cache 会随上下文增长，显存逼近上限是 OOM 的明确前兆。通常显存持续超过 85%～90% 应告警。
    

### 背后知识点

大模型部署监控应分层：

- **资源层**：GPU 显存、GPU 利用率、温度、功耗、CPU、内存、网络。
    
- **服务层**：QPS、错误率、排队长度、并发请求数、超时淘汰率。
    
- **推理性能层**：首 Token 延迟 TTFT、每 Token 输出时延 TPOT/ITL、端到端延迟、Token 吞吐量。
    
- **质量与成本层**：准确率、忠实度、缓存命中率、重新生成率、每千 Token 成本等。
    

### 讨论扩展：准确率到底要不要监控？

**要监控，但分层理解。**

- 准确率不是“服务是否存活”的实时运行指标，而是“答得好不好”的质量指标。
    
- 不能逐请求实时算准确率，因为多数请求没有实时真值，逐条人工标注成本高，且很多问题主观性强。
    
- 准确性监控建议组合：
    
    1. **离线回归评测**：维护业务评测集，模型/Prompt/检索策略变更前跑回归，下降超阈值阻断发布。
        
    2. **在线抽样评估**：定时抽样真实请求，人工或 LLM-as-Judge 评估正确率、忠实度、相关性、格式合规率、拒答率。
        
    3. **在线代理指标**：点踩率、重新生成率、复制率、追问率、会话放弃率、RAG 检索命中率、引用覆盖率、Agent 工具调用成功率、任务完成率、人工接管率。
        
    4. **数据与版本漂移监控**：输入问题分布漂移、检索库更新、模型/Prompt/参数版本变化。
        
    5. **告警策略**：运行指标秒级/分钟级告警；质量指标小时级/天级抽样统计，用环比、置信区间、分场景阈值告警；发布门禁用准确率基线。
        

### 一句话记忆

**运行监控保命，质量监控保效果；准确率必须监控，但不是实时运行核心指标。**

## 第82题：技术文档术语一致性与准确性

### 题干

某公司使用大模型生成技术文档，需要确保术语的一致性和准确性。以下哪些方法组合最有效？

### 选项

- A. 构建术语库并在生成过程中强制使用
    
- B. 使用统一的文档模板
    
- C. 事后人工检查所有术语
    
- D. 实现术语一致性检查工具
    
- E. 依赖模型的术语管理能力
    

### 答案

**A、B、D**

### 逐项解析

- **A 构建术语库并在生成过程中强制使用：正确且核心。**  
    通过术语库约束模型输出，确保标准术语优先、禁用词不出现，从源头保证一致性。
    
- **B 使用统一的文档模板：正确，辅助有效。**  
    统一模板规范文档结构、术语出现位置和表达格式，减少因结构混乱导致的术语不一致。
    
- **C 事后人工检查所有术语：不选为主方案。**  
    人工全量检查成本高、效率低、不可扩展，适合抽检或高风险文档复核，不适合作为规模化主方案。
    
- **D 实现术语一致性检查工具：正确。**  
    自动扫描生成文档，检测术语变体、错用、漏用、前后不一致，是可规模化落地的质量保障手段。
    
- **E 依赖模型的术语管理能力：不选。**  
    模型对术语的“记忆”和一致性控制不可靠，容易出现同义词漂移、幻觉或前后不一致，不能作为保障手段。
    

### 背后知识点

术语一致性保障的有效思路是：

1. **事前约束**：术语库、禁用词表、Prompt 约束。
    
2. **结构化规范**：统一模板、写作规范、字段格式。
    
3. **事后自动校验**：术语一致性检查工具、规则扫描、CI 门禁。
    
4. **人工抽检**：只对高风险内容复核。
    

### 一句话记忆

**术语库强制约束 + 统一模板 + 自动一致性检查工具 = A + B + D。**

## 第84题：系统化控制测验题目难度

### 题干

某教育平台需要生成不同难度的测验题目。以下哪种方法最能系统化控制难度？

### 选项

- A. 随机生成题目
    
- B. 基于布鲁姆分类法明确要求认知层次
    
- C. 要求模型“生成简单题目”
    
- D. 人工编写所有题目
    

### 答案

**B**

### 逐项解析

- **A 随机生成题目：不选。**  
    难度不可控，可能忽难忽易，无法系统化分级。
    
- **B 基于布鲁姆分类法明确要求认知层次：最有效。**  
    布鲁姆分类法把认知过程分为记忆、理解、应用、分析、评价、创造等层级。生成题目时明确要求“考查理解层”或“考查分析层”，可以让模型围绕确定的认知复杂度出题，实现难度分级和批量控制。
    
- **C 要求模型“生成简单题目”：不选。**  
    指令过于模糊，“简单”没有统一标准，模型理解不稳定，难以保证难度一致性。
    
- **D 人工编写所有题目：不选为最佳系统化方法。**  
    质量可控，但成本高、效率低，不适合平台规模化生成不同难度题目。
    

### 背后知识点：布鲁姆分类法

修订版布鲁姆分类法是二维框架：

- **知识维度**：事实性知识、概念性知识、程序性知识、元认知知识。
    
- **认知过程维度**：记忆、理解、应用、分析、评价、创造。
    

“理解”还有子类：解释、举例、分类、总结、推断、比较、说明。

### 讨论扩展：布鲁姆能否用于“知识的理解级别”？

**可以，但要严格表述。**

- 布鲁姆更准确地说是**认知过程/认知掌握层级框架**，不是“知识本身难度”的静态框架。
    
- 同一知识点可以设计不同认知层级任务。例如“牛顿第二定律”：
    
    - 记忆：复述 F=maF=ma
        
    - 理解：解释各量含义及关系
        
    - 应用：给定质量与加速度计算合力
        
    - 分析：分析多物体系统中各力关系
        
    - 评价：判断解题方案是否合理
        
    - 创造：设计实验验证定律
        
- 避免三个误用：
    
    1. 不要给知识点静态贴标签，不能说“牛顿第二定律属于应用级知识”。
        
    2. 不要把它当唯一难度标尺，难度还受知识广度、推理步数、情境复杂度、计算量、干扰项影响。
        
    3. 层级不是绝对线性，不是所有学习都必须严格从记忆到创造。
        
- 若要专门评估理解深度，可配合 **SOLO 分类法**（前结构、单点、多点、关联、拓展抽象）和 **DOK 深度知识层级**。
    

### 一句话记忆

**用认知层次框架把“难度”结构化，再让模型按层级生成题目。**

## 第87题：内容审核降低误判

### 题干

某内容审核系统使用大模型识别违规内容，但误判率较高。以下哪种方法最能降低误判？

### 选项

- A. 降低判断阈值
    
- B. 提供更多违规内容示例
    
- C. 要求模型“严格审核”
    
- D. 结合规则引擎和模型判断
    

### 答案

**D**

### 逐项解析

- **A 降低判断阈值：不选。**  
    通常会让判定更宽松，可能减少“误杀”，但会增加漏放，不一定降低总体误判率。
    
- **B 提供更多违规内容示例：不选为“最能降低误判”。**  
    能提升违规识别能力，但主要改善召回、减少漏放；如果误判主要是正常内容被误杀，更多违规示例可能让模型更敏感，反而加剧误杀。
    
- **C 要求模型“严格审核”：不选。**  
    往往让模型更保守，可能增加误杀，不能有效降低误判。
    
- **D 结合规则引擎和模型判断：最系统有效。**  
    规则引擎处理确定性高的违规词、格式、黑名单；模型处理语义和上下文；两者结合可规则兜底、模型复核、分级判定，降低误判。
    

### 讨论扩展：B 为什么不行？

B 不是完全没用，而是作为“最能降低误判”不够，且可能适得其反。原因：

1. **只增加违规正例，缺少正常负例和边界样本。**  
    误判常发生在边界场景，如正常内容含敏感词但语境合法。更多违规示例不会教模型“哪些看起来像违规但其实不违规”。
    
2. **可能加剧误杀。**  
    如果当前误判主要是正常内容被误判，继续喂更多违规示例会让模型更倾向判违规。
    
3. **示例不等于系统化控制。**  
    内容审核需要确定性规则、黑白名单、阈值校准、分级处置、人工复核；仅靠示例是“软约束”。
    
4. **容易过拟合表面特征。**  
    模型可能记住示例表面词句，而不是理解违规边界，遇到新变体泛化差。
    
5. **没有解决阈值和判定策略问题。**  
    误判率高可能来自阈值过低、类别不平衡、模型校准差，B 没有直接处理这些机制问题。
    

### 背后知识点

内容审核更完整的组合：  
**规则引擎 + 模型判断 + 高质量负例/边界样本 + 阈值校准 + 分级处置 + 人工复核。**

### 一句话记忆

**规则处理确定性，模型处理语义模糊性；只加违规示例可能让模型更“敏感”，不一定更“准确”。**

## 第90题：客户反馈处理任务组合

### 题干

某企业使用大模型处理客户反馈，要求“从反馈中提取问题类型、客户满意度、联系方式，并生成统计报表”。以下哪些任务类型需组合实现？

### 选项

- A. 命名实体识别（提取联系方式）
    
- B. 文本分类（判断问题类型、客户满意度）
    
- C. 文本摘要（生成统计报表）
    
- D. 信息抽取（提取问题类型、满意度标签）
    
- E. 仅依赖单一检测模型
    

### 答案

**A、B、D**  
更准确地说：**核心是 A + B，D 可作为信息抽取环节组合。**

### 逐项解析

- **A 命名实体识别（提取联系方式）：正确。**  
    电话号码、邮箱、订单号等更适合用 NER 抽取。
    
- **B 文本分类（判断问题类型、客户满意度）：正确。**  
    问题类型和满意度通常是类别标签，用分类模型判断更直接。
    
- **C 文本摘要（生成统计报表）：不选。**  
    统计报表需要先得到结构化数据，再做计数、分组、聚合、趋势统计，最后由报表模块生成。文本摘要做的是“把长文本压缩成短文本”，不能替代统计聚合。
    
- **D 信息抽取（提取问题类型、满意度标签）：可组合。**  
    广义上可把反馈转为结构化字段。问题类型、满意度更直接是文本分类，但信息抽取可作为结构化信息抽取环节。
    
- **E 仅依赖单一检测模型：不选。**  
    客户反馈处理需要 NER、分类/抽取、统计聚合等多个环节组合。
    

### 讨论扩展：C 到底错在哪？还需要文本摘要吗？

C 的问题在于**任务类型映射错了**：把“生成统计报表”归为“文本摘要”。

统计报表核心流程：

> 抽取结构化字段 → 分类/打标 → 按维度聚合统计 → 生成表格/图表/报表

例如问题类型分布、满意度分布、联系方式抽取数量、缺失率等，都是**统计聚合**，不是文本摘要。

实际系统**不是必需文本摘要**。但如果报表还要求：

- 生成“本周客户反馈总体情况”的文字概述；
    
- 对典型反馈做摘要展示；
    
- 生成自然语言版分析报告；
    

可以额外加**文本摘要**作为辅助功能。但它是“报表的文字说明/洞察生成”，不是“统计报表本身”。

### 背后知识点

任务类型映射：

- 提取联系方式 → NER。
    
- 判断问题类型/满意度 → 文本分类。
    
- 转结构化字段 → 信息抽取。
    
- 压缩长文本 → 文本摘要。
    
- 计数、分组、聚合、趋势 → 统计报表模块。
    

### 一句话记忆

**统计报表 ≠ 文本摘要；核心是 NER + 分类/信息抽取 + 统计聚合报表。**

## 第93题：新闻摘要保持中立客观

### 题干

某新闻摘要系统需要保持中立客观。以下哪种方法最能减少模型偏见？

### 选项

- A. 使用多个模型投票
    
- B. 要求多个角度分析
    
- C. 基于事实性信息生成摘要
    
- D. 人工编写摘要
    
- E. 让模型直接读取原始文档格式，无需解析
    

### 答案

**C**

### 逐项解析

- **A 使用多个模型投票：不选为最佳。**  
    只能降低单个模型的随机偏差，不能消除训练数据中的系统性偏见；多个模型可能共享同类偏见。
    
- **B 要求多个角度分析：不选为最佳。**  
    有助于平衡视角，但“多角度”不等于“中立客观”，可能引入更多观点甚至造成立场混杂。
    
- **C 基于事实性信息生成摘要：最有效。**  
    摘要只陈述原文中的事实性信息，避免加入模型主观评价、情绪色彩和立场倾向，可以过滤评论性、煽动性、观点性内容，减少模型自身偏见对摘要的污染。
    
- **D 人工编写摘要：不选为最佳系统方法。**  
    质量可能高，但成本高、不可规模化，且人工同样可能带有偏见。
    
- **E 直接读取原始文档格式、无需解析：不选。**  
    与减少偏见无关，反而可能因格式噪声影响摘要质量。
    

### 背后知识点

中立客观摘要的完整做法：  
**事实性信息抽取 + 观点与事实分离 + 中立性提示约束 + 偏见检测/人工抽检。**

### 一句话记忆

**中立客观的关键是“基于事实”，不是“多模型投票”或“多角度分析”。**

## 第100题：代码生成任务额外上下文

### 题干

为了提升大模型在代码生成任务上的性能，除了提供函数签名和注释外，以下哪种额外的上下文信息对模型最有帮助？

### 选项

- A. 项目所在的文件目录结构
    
- B. 相关的其他函数或类的代码实现
    
- C. 开发者的编程经验水平
    
- D. 计算机的硬件配置
    

### 答案

**B**

### 逐项解析

- **A 项目所在的文件目录结构：有一定辅助作用，但不如 B 直接。**  
    目录结构是导航线索，但本身不含代码语义；若模型没有文件读取/代码检索工具，无法真正“按图索骥”，只能猜。
    
- **B 相关的其他函数或类的代码实现：最有效。**  
    提供被调用函数、类、数据结构、接口定义、异常处理方式、依赖库调用方式、项目命名风格等，能帮助模型理解依赖关系、参数含义、返回类型和调用约定，生成更可编译、可维护、减少幻觉的代码。
    
- **C 开发者的编程经验水平：不选。**  
    与代码生成质量无直接关系。
    
- **D 计算机的硬件配置：不选。**  
    与代码逻辑生成基本无关。
    

### 讨论扩展：A 和 B 到底怎么选？

你的想法有道理：目录结构确实能提供项目组织信息。但在这道题语境下，**A 不如 B 直接有效**。

- 目录结构只是“地图”：
    
    text
    
    src/
      services/
        user_service.py
      models/
        user.py
      utils/
        validator.py
    
    模型看到 `utils/validator.py` 只知道“可能和校验有关”，不知道具体函数名、参数、异常处理、返回结构、项目约定。
    
- “按图索骥”有前提：模型必须具备**文件读取工具、代码检索工具、Agent 循环能力**。题目没有说系统支持模型自主读文件。若只是把目录结构塞进上下文，模型无法真正自行寻找例子。
    
- 路径名可能模糊甚至误导：`common/helpers.py`、`core/manager.py` 看名字很难判断是否相关。
    
- 上下文窗口有限：目录结构可能很长但信息密度低；B 直接提供相关实现，信息密度高、相关性直接。
    

更准确的说法：

- 如果系统是仓库级代码 Agent，具备检索和读文件能力：**A 可作辅助导航信息**，但真正有用的还是最终读到的相关代码实现 B。
    
- 如果只是给模型补充上下文：**B 是最有帮助的额外上下文。**
    

### 背后知识点

代码生成最需要的上下文：

- 被调用函数或类的实现；
    
- 数据结构、接口定义；
    
- 项目命名规范、异常处理方式；
    
- 依赖库调用方式；
    
- 相邻模块代码风格。
    

### 一句话记忆

**A 是地图，B 是实际参考代码；写代码时最需要的是相关实现。**

<a id="第13题"></a>

## 第13题：学术论文助手引用格式

### 题干

在构建学术论文助手时，需要模型引用特定格式的参考文献。以下哪种方法最有效？

### 选项

- A. 要求模型“使用 APA 格式”
    
- B. 提供 APA 格式的引用示例
    
- C. 使用专门的引用生成工具
    
- D. 要求模型自行决定格式
    

### 答案

**C**

### 逐项解析

- **A 要求模型“使用 APA 格式”：不选为最佳。**  
    指令太模糊，模型容易在标点、作者缩写、年份、DOI、页码等细节上出错。
    
- **B 提供 APA 格式的引用示例：不选为最佳。**  
    有帮助，但只是“软约束”，模型仍可能模仿不准确或产生幻觉。
    
- **C 使用专门的引用生成工具：最有效。**  
    引用生成工具基于结构化元数据和引用样式规则（如 CSL、BibTeX、Zotero、citation-js 等）生成引用，具有确定性、可校验、可批量处理的优势，最能保证格式一致和准确。
    
- **D 要求模型自行决定格式：不选。**  
    不可控，无法保证符合指定规范。
    

### 背后知识点

稳妥的工程做法：

> 模型负责抽取文献元数据（作者、标题、年份、期刊、DOI 等），专门引用工具负责按 APA 格式生成引用，模型或校验器再做最终检查。

### 一句话记忆

**格式严格的任务交给确定性工具；模型负责理解与抽取，不负责“凭感觉排版”。**

<a id="跨题知识点总结"></a>

## 跨题知识点总结

### 1. 大模型应用监控要分层

- **资源层**：显存、GPU 利用率、温度、功耗、CPU、内存、网络。
    
- **服务层**：QPS、错误率、排队长度、并发数、超时淘汰率。
    
- **推理性能层**：TTFT、TPOT/ITL、端到端延迟、Token 吞吐量、Prefill/Decode 分阶段耗时。
    
- **质量与成本层**：准确率、忠实度、缓存命中率、重新生成率、每千 Token 成本。
    

**准确率必须监控，但属于质量监控层，不是实时运行核心指标。**

### 2. 质量保障常用三段式

**事前约束 + 结构化规范 + 事后自动校验**

- 术语一致性：术语库 + 模板 + 检查工具。
    
- 引用格式：元数据抽取 + 引用生成工具 + 校验。
    
- 内容审核：规则引擎 + 模型判断 + 负例/边界样本 + 阈值校准 + 人工复核。
    

### 3. 任务类型要映射准确

- 提取联系方式 → **NER**。
    
- 判断问题类型/满意度 → **文本分类**。
    
- 转结构化字段 → **信息抽取**。
    
- 压缩长文本 → **文本摘要**。
    
- 计数、分组、聚合、趋势 → **统计报表模块**。
    

**统计报表 ≠ 文本摘要；文本摘要可作为报表的文字概述增强，但不是核心必需。**

### 4. 难度控制要结构化

布鲁姆分类法适合把“难度”转化为**认知层次要求**：  
记忆、理解、应用、分析、评价、创造。  
但应表述为“认知过程层级”，不要给知识点静态贴标签；可配合 SOLO、DOK。

### 5. 内容审核不要只加正例

只提供更多违规示例主要提升召回、减少漏放，可能让模型更敏感、加剧误杀。  
降低误判需要：规则引擎 + 模型 + 负例/边界样本 + 阈值校准 + 分级处置 + 人工复核。

### 6. 代码生成上下文看“相关性”和“信息密度”

目录结构是导航线索；相关函数/类实现是直接参考代码。  
若系统具备代码检索/文件读取 Agent 能力，目录可辅助导航，但最终最有帮助的是相关实现。

### 7. 严格格式任务优先工具化

APA、MLA、GB/T 7714、IEEE 等引用格式细节严格，适合用 CSL、BibTeX、Zotero、citation-js 等确定性工具生成，模型负责抽取元数据和最终检查。

<a id="易错点与复习提示"></a>

## 易错点与复习提示

1. **“准确率不用监控吗？”**  
    要监控，但它是质量指标，不是实时运行核心指标。监控方式：离线评测 + 在线抽样 + 代理指标 + 漂移监控 + 发布门禁。
    
2. **“更多违规示例为什么不能降低误判？”**  
    它主要增强违规识别、偏向召回；如果误判是正常内容被误杀，更多违规示例可能让模型更敏感。需要负例、边界样本和规则/阈值配合。
    
3. **“统计报表不是文本摘要吗？”**  
    不是。统计报表核心是结构化抽取后的计数、分组、聚合、趋势；文本摘要只是可选的文字概述增强。
    
4. **“目录结构不是能按图索骥吗？”**  
    需要模型具备文件读取/代码检索工具；仅给目录结构信息密度低、路径可能误导。相关函数/类实现更直接有效。
    
5. **“布鲁姆分类法是不是给知识点分等级？”**  
    更准确是认知过程层级框架。同一知识点可以考记忆，也可以考创造；应结合知识维度使用。
    
6. **多选题看“组合最优”**  
    例如第82题是 A+B+D 组合；第90题核心是 A+B，D 可作信息抽取组合；不要因为某个选项“有一点用”就选，要看是否最有效、是否任务映射正确。
