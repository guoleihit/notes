# 今日错题总结（RAG 与大模型应用）

> 本文档整理了今天讨论中涉及的选择题、易错点及详细解析，涵盖 RAG 检索优化、文档切片、评估指标、模型微调、RAGAS 中文适配等内容。

---

## 1. RAG 系统回答准确性不高的原因与改进措施

**题目：**  
在开发基于 RAG 的智能问答系统时，发现系统在某些领域的回答准确性不高。可能的原因和相应的改进措施包括：

A. 检索到的文档质量不高，需要优化文档预处理和向量化  
B. 模型理解能力有限，需要更换更强大的基础模型  
C. 提示词设计不合理，需要优化问题重构和答案生成提示  
D. 用户问题太复杂，建议用户简化问题  
E. 检索范围过窄，需要调整相似度阈值召回更多相关文档

**正确答案：A、B、C、E**

**解析：**

- **A 正确**：文档质量、切分、向量化直接影响检索效果。
    
- **B 正确**：生成阶段依赖基础模型的理解与推理能力，模型弱则答案易错。
    
- **C 正确**：提示词影响查询重构、上下文利用和答案生成。
    
- **E 正确**：检索范围过窄、阈值过高会导致相关文档未被召回。
    
- **D 不选**：应通过查询分解、多轮澄清、HyDE 等系统侧优化，而非简单要求用户简化问题。
    

**易错点：** D 看似合理，但把系统问题转嫁给用户，不是技术改进方向。

## 2. 评估生成文本词序与词组匹配的指标

**题目：**  
在评估大模型生成文本的质量时，以下哪个指标主要用于衡量生成文本与参考文本在词序和词组匹配上的相似度？

A. ROUGE  
B. BLEU  
C. Perplexity  
D. F1 Score

**正确答案：B. BLEU**

**解析：**

- **BLEU**：基于 n-gram 词组重叠，关注生成文本与参考文本的词组匹配，常用于机器翻译。
    
- **ROUGE**：常用于摘要评估，侧重召回率。
    
- **Perplexity**：衡量语言模型困惑度，不直接依赖参考文本。
    
- **F1 Score**：通用指标，非专门衡量词序和词组匹配。
    

**易错点：** ROUGE 和 BLEU 容易混淆，BLEU 更强调精确匹配和词序。

## 3. 微调大模型验证集损失不再下降，哪种做法不太可能提升性能？

**题目：**  
在微调大模型以适应某个垂直领域时，观察到验证集上的损失在几个轮次后就不再显著下降。以下哪种做法不太可能带来进一步的性能提升？

A. 尝试调整学习率或使用不同的优化器  
B. 检查并清洗训练数据中的噪声  
C. 显著增加模型的深度和宽度  
D. 为模型提供该领域更丰富的上下文信息（如通过 RAG）  
E. 追求模型在所有指标上的最高分数，忽略其他因素

**正确答案：C. 显著增加模型的深度和宽度**

**解析：**

- **A、B、D** 都是常规有效的微调优化手段。
    
- **C 不选**：微调阶段通常不改变模型结构。显著增加深度和宽度等于改架构，需重新预训练，且垂直领域数据有限，容易过拟合，验证损失未必下降。
    
- **E** 虽不合理，但题目问“不太可能带来性能提升”，C 是最直接错误的选项。
    

**补充说明：**  
“显著增加模型的深度和宽度”指把神经网络做得更大：深度=层数，宽度=隐藏维度、FFN 维度、注意力头数等。这属于模型缩放，不是普通微调。

## 4. 稠密向量检索对实体名称效果差，如何改进？

**题目：**  
在优化 RAG 系统的检索器时，发现当前使用的稠密向量检索器对于某些包含特定实体名称的查询效果不好，而传统的关键词检索（如 BM25）在这些查询上表现更好。以下哪种架构改进最能兼顾两种检索方式的优势？

A. 完全用关键词检索替换稠密向量检索  
B. 采用混合检索（Hybrid Retrieval）策略，合并两种检索方式的结果  
C. 增加稠密向量检索的维度  
D. 要求用户避免使用实体名称进行查询

**正确答案：B. 采用混合检索（Hybrid Retrieval）策略，合并两种检索方式的结果**

**解析：**

- 稠密检索擅长语义匹配，BM25 擅长精确匹配实体、专有名词。
    
- 混合检索同时运行两路，通过加权融合、RRF、重排序等合并结果，兼顾两者优势。
    
- A 丢失语义能力；C 不一定解决精确匹配；D 转嫁问题给用户。

## 5. 优化 RAG 系统提升检索质量的方法

**题目：**  
在优化 RAG 系统时，以下哪些方法可以提升检索质量？

A. 优化文本分块策略  
B. 尝试不同的嵌入模型  
C. 调整检索相似度阈值  
D. 使用重排序技术对初步检索结果进行精排  
E. 增加每次检索返回的文档数量

**正确答案：A、B、C、D**

**解析：**

- **A**：合理分块保证语义完整。
    
- **B**：嵌入模型决定向量表示质量。
    
- **C**：阈值平衡召回率与准确率。
    
- **D**：重排序可显著提升最终相关性排序。
    
- **E 不选**：增加 top-k 可能提升召回率，但也会引入噪声，降低精度。通常需配合重排序和过滤，单独增加数量不等于提升检索质量。
    

**易错点：** E 有条件可能提升召回，但“检索质量”通常指最终上下文相关性，故不选。

## 6. LlamaIndex SimpleDirectoryReader 的返回结果

**题目：**  
LlamaIndex 在创建 RAG 应用时，第一步 SimpleDirectoryReader 是将知识文件解析为（）？

A. Document 对象  
B. 索引 index  
C. 元素为 Document 对象的列表  
D. 包含所有文字信息的字符串  
E. 合规性和安全性认证

**正确答案：C. 元素为 Document 对象的列表**

**解析：**  
`SimpleDirectoryReader.load_data()` 返回 `List[Document]`，每个元素是一个 `Document` 对象，包含文本和元数据。之后才用于构建索引。

## 7. 极简查询“找张伟”检索不到，最合理的技术改进

**题目：**  
有用户使用“找张伟”这类极简搜索，RAG 系统经常没能检索到所需文档，最合理的技术改进是什么？

A. 将所有文档发布成内部 Wiki  
B. 在回答时修改用户的问题  
C. 在检索前先用大模型进行问题改写扩充  
D. 让用户输入更多关键词

**正确答案：C. 在检索前先用大模型进行问题改写扩充**

**解析：**

- 极简查询信息量不足，直接检索召回率低。
    
- 应在检索前用 LLM 进行 Query Rewriting / Multi-Query / HyDE，扩展为“张伟 联系方式 部门 邮箱”等。
    
- A 不解决检索；B 在回答时修改已太晚；D 转嫁给用户。

## 8. 召回切片相关但不含答案，最优先排查方向

**题目：**  
你发现 RAG 应用召回的切片内容虽然和问题相关，但并不包含真实答案。最优先的排查和改进方向是什么？

A. 检查 Embedding 模型的类型及版本  
B. 尝试调低 top_k，减少召回范围  
C. 优先在弱关联层隐藏检索结果，只呈现大模型的最终回答  
D. 为每一条切片附详细的前置叙述，希望大模型自动补齐缺失内容

**正确答案：A. 检查 Embedding 模型的类型及版本**

**解析：**

- 问题本质是检索器只匹配到主题相关，未精确定位答案片段。
    
- 优先检查嵌入模型是否适合检索、版本是否一致、是否按非对称检索方式编码。
    
- B 可能漏召回；C 掩盖问题；D 鼓励幻觉。
    

**补充说明：**

- **适合检索任务的嵌入模型**：需在检索基准上表现好，支持非对称检索，按模型要求加 query/passage 前缀。
    
- **对称检索 vs 非对称检索**：RAG 通常是非对称检索（短查询找长文档），需正确使用查询侧和文档侧编码方式，否则向量空间不对齐。

## 9. 哪些情况可能导致大模型检索不准确？

**题目：**  
以下哪些情况可能导致大模型检索不准确？

A. 文档中包含大量的图片信息，而当前的文档解析器无法有效提取和理解图片内容。  
B. 使用了基于深度学习的语义搜索引擎，但模型训练数据不足，导致检索结果不准确。  
C. 文档中包含复杂的表格结构，而简单的文本解析器无法理解表格单元格之间的关系。  
D. 使用了复杂的文档解析器，导致解析速度慢，影响检索效率。  
E. 索引构建过程中使用了错误的 embedding 模型导致语义相似度计算错误。  
F. 文档切片时，仅简单地按照字符长度进行分割丢失了文档的语义信息。

**正确答案：A、B、C、E、F**

**解析：**

- **A**：图片信息丢失。
    
- **B**：语义检索模型训练不足，向量表示差。
    
- **C**：表格结构丢失，关系错乱。
    
- **E**：索引与查询嵌入模型不一致，相似度计算错误。
    
- **F**：固定长度切分破坏语义完整性。
    
- **D 不选**：解析速度慢影响效率，不直接导致准确性下降。
    

**补充说明：**  
选项 B 中的“模型”指语义搜索引擎背后的深度学习嵌入模型。现代 RAG 检索依赖深度学习模型，训练数据不足会直接影响检索准确性。

## 10. 符合基于语义的文档切片理念的描述

**题目：**  
以下哪些描述符合基于语义的文档切片的理念？

A. 使用机器学习模型对文档进行语义分析，并根据语义边界进行切分。  
B. 在 Chunk 中添加上下文信息，例如标题、父级列表项等。  
C. 将代码模块单独切出来，并标注其编程语言。  
D. 将文档按照固定长度进行切分。  
E. 将表格的每个单元格作为一个独立的 Chunk。  
F. 根据文档的结构，例如标题、段落、列表等进行切分。

**正确答案：A、B、C、F**

**解析：**

- 语义切片核心是保持语义完整性和结构关系。
    
- A 语义边界切分、B 添加上下文、C 代码模块单独切分、F 按文档结构切分均符合。
    
- D 固定长度是机械切分；E 破坏表格结构。

## 11. 复杂表格 Markdown 文档 RAG 问答错误的解决方案

**题目：**  
用户上传了一个包含复杂表格的 Markdown 文档，使用默认的 RAG 流程进行问答。用户提问关于表格中特定单元格含义的问题时，大模型经常给出错误或不相关的答案。请问以下哪些方案可以尝试解决这个问题？

A. 对用户提问进行预处理，提取表格相关的关键词。  
B. 在文档切片时，将表格的行列信息添加到每个单元格的 Chunk 中。  
C. 将表格转换成 JSON 格式，然后使用 JSON Loader 加载数据。  
D. 使用 OCR 技术识别表格中的文字，并将识别结果添加到文本中。  
E. 使用更强大的 Embedding 模型。  
F. 增加训练数据，让大模型更好地理解表格内容。

**正确答案：A、B、C、E**

**解析：**

- **A**：提取表格关键词，辅助检索。
    
- **B**：为单元格 Chunk 附加行列信息，保留结构。
    
- **C**：转 JSON 保留键值对和层级关系。
    
- **E**：更强 Embedding 作为辅助，但需先解决结构丢失。
    
- **D 不选**：Markdown 文本可解析，无需 OCR。
    
- **F 不选**：RAG 问题主要在检索和文档表示，非微调能解决。

## 12. 将 RAGAS 评测适配到中文问答场景的有效方法

**题目：**  
为了将 RAGAS 评测适配到中文问答场景，有哪些有效方法？

A. 使用中文能力较强的大模型  
B. 将 RAGAS 自带的 prompt 翻译为中文再传入  
C. 在 faithfulness 中修改 json.dumps 函数，使其返回中文而非 unicode 码  
D. 在 System prompt 中提醒大模型：你要适配到中文问答场景

**正确答案：A、B、C**

**解析：**

- **A**：评估模型的中文能力直接影响评测可靠性。
    
- **B**：RAGAS 提示词为英文，需翻译适配，可使用 `adapt_prompts(language="chinese")` 或手动重写。
    
- **C**：`json.dumps` 默认 `ensure_ascii=True` 会将中文转义，应改为 `ensure_ascii=False`。
    
- **D 不选**：RAGAS 通过 `adapt_prompts` 或替换模型适配，而非通用 System prompt。

## 13. 分类任务标签转化为数字形式的术语

**题目：**  
数据预处理中，将分类任务的标签转化为模型可理解的数字形式称为什么？

A. 文本标准化  
B. 词嵌入 (Word Embedding)  
C. 特征缩放  
D. 标签编码 (Label Encoding)

**正确答案：D. 标签编码 (Label Encoding)**

**解析：**  
将“猫、狗、鸟”映射为 0、1、2 等整数，称为标签编码。其他选项：文本标准化是文本清洗；词嵌入是词向量；特征缩放是数值归一化。

## 14. 相邻段落被拆分导致上下文缺失，如何提升答案准确度？

**题目：**  
RAG 应用在检索时共召回了 10 条切片，其中 3 条高度相关，但这 3 条内容都来自相邻段落，却被系统拆分成不同切片，从而导致回答时缺失连贯的上下文信息。哪些方案可进一步提升答案准确度？

A. 使用按照语义的切片策略，切分出语义更完整的切片  
B. 调整切片大小使其覆盖完整更大段落范围  
C. 采用滑动窗口策略生成重叠的文本切片  
D. 提高 temperature 参数控制生成多样性

**正确答案：A、B、C**

**解析：**

- **A**：语义切片保证单元完整。
    
- **B**：增大切片覆盖更大段落。
    
- **C**：滑动窗口重叠减少边界信息丢失。
    
- **D 不选**：temperature 控制生成随机性，与检索连贯性无关，提高反而可能降低稳定性。

|5|增加返回文档数量|可能提升召回，但降低精度，不算提升检索质量|

|11|OCR 解决表格？|Markdown 无需 OCR，需结构化处理|

|14|提高 temperature|与上下文连贯性无关|
