## 1. 相似度阈值与召回数量

**题目**：小明在创建 RAG 应用时，知识库配置部分的相似度阈值设置较高，在应用创建界面设置检索片段数为 5，进行提问时检索到高于相似度阈值的文本块只有 3 个，最后实际召回的文本块有几个？  
**选项**：A. 2 B. 3  
**答案**：**B. 3**

**解析**：  
检索片段数 = 5 是上限，不是必须返回的数量。相似度阈值过滤后只有 3 个文本块高于阈值，因此实际召回就是 3 个。

## 2. 提高知识索引性能的技术

**题目**：为了提高知识索引的性能，以下哪项技术涉及到了使用更先进的嵌入模型？  
**选项**：  
A. Decomposition 问题分解  
B. CRAG 互联网检索  
C. BGE 新嵌入模型  
D. Step Back 问题摘要

**答案**：**C. BGE 新嵌入模型**

**解析**：  
BGE 是一类先进的文本嵌入模型，用于提升向量化表示质量，直接提升知识索引和检索性能。其他选项属于查询优化或检索策略，不涉及嵌入模型本身。

## 3. 文档拆分更小分块的适合场景

**题目**：在 RAG 系统中，以下哪种情况最适合将文档拆分成更小的分块？  
**选项**：  
A. 文档内容非常简短，总共只有几句话  
B. 文档内容高度相关，主题单一  
C. 文档内容包含多个主题，信息量较大  
D. 文档格式简单，例如纯文本文件

**答案**：**C. 文档内容包含多个主题，信息量较大**

**解析**：  
多主题、信息量大的文档如果不拆分，向量表示会被“平均化”，检索精度下降。拆成小分块后，每个块主题更聚焦，更容易被准确召回。

## 4. LlamaIndex 读取文档并创建索引（存储目录不存在）

**题目**：在借助 LlamaIndex 构建问答机器人过程中，如果存储目录不存在，应使用哪个类来读取文档并创建索引？  
**选项**：  
A. VectorStoreIndex  
B. SimpleDirectoryReader  
C. StorageContext  
D. load_index_from_storage

**答案**：**B. SimpleDirectoryReader**

**解析**：  
存储目录不存在时，需要从原始文档重新读取并创建索引。

python

from llama_index.core import SimpleDirectoryReader, VectorStoreIndex
documents = SimpleDirectoryReader("data").load_data()
index = VectorStoreIndex.from_documents(documents)

---

## 5. 存储目录已存在时的加载方式

**题目**：如果存储目录已经存在了呢？  
**答案**：**D. load_index_from_storage**

**解析**：  
存储目录已存在说明之前已持久化过索引，直接加载即可。

python

from llama_index.core import StorageContext, load_index_from_storage
storage_context = StorageContext.from_defaults(persist_dir="./storage")
index = load_index_from_storage(storage_context)

## 6. 不能保证“关键数据的语义独立性与完整性”的做法

**题目**：在开发基于大语言模型的 RAG 应用过程中，以下哪种做法不能保证“关键数据的语义独立性与完整性”？  
**选项**：  
A. 将标题下的所有文本合成一个段落  
B. 针对表格中每一行单元格的数据，扩写加上各级标题、表格头部的字段说明  
C. 确保每个语义单元都有清晰的边界和完整的上下文信息  
D. 对不同的数据类型（例如文本、表格、图片）采用不同的处理方式

**答案**：**A. 将标题下的所有文本合成一个段落**

**解析**：  
把标题下所有文本合成一段会混合多个子主题，破坏语义独立性和完整性。其他选项都是保持语义完整性的正确做法。

## 9. 大模型 vs Embedding 模型的使用场景

**补充知识点**：

- **大模型**：生成、理解、判断、推理、规划、提取观点、问题改写。
    
- **Embedding 模型**：向量化、相似度计算、检索召回、聚类、去重。
    

**RAG 流程中的分工**：

1. 建索引：Embedding 模型将文档块向量化。
    
2. 检索：Embedding 模型将问题向量化并算相似度。
    
3. 生成：大模型根据召回内容生成答案。
    
4. 评估：大模型提取观点、判断正确性；Embedding 模型辅助算语义相似度。

## 10. 适合逻辑性强、内容专业文档的切片方法

**题目**：在文档切片过程中，以下哪种切片方法适合文档逻辑性强、内容专业的场景？  
**选项**：  
A. 语义切片  
B. Token 切片  
C. 句子切片  
D. 句子窗口切片

**答案**：**A. 语义切片**

**解析**：  
语义切片根据语义结构和逻辑边界切分，能保证每个切片围绕完整语义单元，适合技术文档、法律合同、医学文献等专业场景。

## 11. 其他切片方法的使用场景

|切片方法|适合场景|不太适合|
|---|---|---|
|Token 切片|杂乱文本、快速处理、基线方案|专业文档、逻辑性强|
|句子切片|FAQ、短文本、细粒度检索|长逻辑段落|
|句子窗口切片|对话、叙述、需要上下文|结构复杂专业文档|
|语义切片|专业文档、逻辑性强|计算成本敏感|
|标题/章节切片|结构清晰文档（Markdown、手册）|无结构文本|
|递归切片|通用长文档、混合格式|规则设计复杂|
|表格/图片切片|多模态、结构化数据|纯文本简单场景|

## 12. GraphRAG 技术的优势

**题目**：GraphRAG 技术的优势包括哪些？  
**选项**：  
A. 准确回答具体问题  
B. 处理需要深入理解的复杂查询  
C. 提高模型训练速度

**答案**：**A、B**

**解析**：

- A：GraphRAG 能利用知识图谱中的实体和关系，提高具体问题的回答准确性。
    
- B：核心优势，通过图结构支持多跳推理，处理复杂查询。
    
- C：不涉及提高模型训练速度，反而可能增加图构建开销。

**选项**：  
A. query  
B. chunks  
C. embedding_models  
D. cosine_similarity

**答案**：**A、B、C**

- B chunks：文档切片
    
- C embedding_models：要对比的多个嵌入模型
    
- D cosine_similarity：是内部使用的相似度计算方法，不是输入参数。

## 17. 检索后减少无关信息的方法

**题目**：在检索召回阶段，以下哪些方法用于在检索后减少无关信息？  
**选项**：  
A. 重排序  
B. 滑动窗口检索

**答案**：**A、B**（注意：标准答案可能只选 A，但实际两者均可减少无关信息）

**解析**：

- **重排序**：初步召回后重新打分排序，过滤低相关内容。
    
- **滑动窗口检索**：在长文档中定位最相关的一小段，只输出窗口内内容，减少无关信息进入生成阶段。
    

> 有课程或题目可能只将“重排序”视为检索后处理，但滑动窗口检索在长文档场景下也能起到减少无关信息的作用。以课程答案为准。

## 20. 私有知识问答场景中直接传入私域参考信息的问题

**题目**：在私有知识问答场景中，直接传入私域知识相关的参考信息可能导致哪些问题？  
**选项**：  
A. 提示词长度有限  
B. 模型处理效率降低  
C. 模型无法理解私域知识  
D. 模型生成内容不准确

**答案**：**A、B、D**

**解析**：

- A：容易超出上下文窗口限制。
    
- B：输入越长，推理开销越大，效率降低。
    
- C：不准确，大模型通常能理解私域文本，问题在于信息过多、噪声大。
    
- D：无关内容、矛盾信息会干扰模型，导致生成不准确或幻觉。

## 22. 加载本地索引文件时可设置的参数

**题目**：在加载本地索引文件时，以下哪些参数可以设置？  
**选项**：  
A. 存储路径  
B. 使用的 embedding 模型  
C. API Key

**答案**：**A、B、C**（根据课程答案，但 C 是间接设置）

**解析**：

- **A. 存储路径**：必需，通过 `StorageContext.from_defaults(persist_dir=...)` 指定。
    
- **B. embedding 模型**：建议设置，通过 `load_index_from_storage(..., embed_model=...)` 传入，需与创建时一致。
    
- **C. API Key**：并非 `load_index_from_storage` 的直接参数，而是初始化 embedding 模型时必须提前配置的环境前置条件。课程可能将“配置 API Key”视为加载流程中可设置的环节。
    

> **标准 LlamaIndex 用法中，API Key 通过环境变量或初始化模型时传入。**

## 复习要点速记

1. **召回数量**：受相似度阈值限制，不是必须达到检索片段数。
    
2. **嵌入模型**：BGE、OpenAI text-embedding-3 系列。
    
3. **切片方法**：专业逻辑强 → 语义切片；多主题大信息量 → 小分块。
    
4. **LlamaIndex**：存储目录不存在 → SimpleDirectoryReader + VectorStoreIndex；已存在 → load_index_from_storage。
    
5. **评估指标**：
    
    - AnswerCorrectness：大模型提取观点 + Embedding 算语义相似度。
        
    - Context Precision：结合 question 和 ground_truth 判断相关性，逐步计算 precision。
        
6. **检索优化**：重排序、滑动窗口检索可减少无关信息。
    
7. **GraphRAG**：优势是复杂查询和多跳推理，也能提升具体问题准确性。
    
8. **私有知识直接传入**：提示词长度、处理效率、生成准确性都会受影响。
    
9. **大模型 vs Embedding**：生成/理解/判断用大模型；向量化/相似度/检索用 Embedding。
