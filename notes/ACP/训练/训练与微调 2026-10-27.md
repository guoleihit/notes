## 第130题（多选）

**题目：**  
你需要大模型从客户邮件中提取结构化数据（如姓名、订单号、问题类型），以下哪两个选项有助于你达成这一目标？

A. 调低温度参数（Temperature）以降低随机性  
B. 要求模型分两步操作：先总结邮件内容，再提取字段  
C. 在任务目标中明确“输出 JSON 格式”  
D. 提供你期望的 JSON 结构示例  
E. 完全依赖模型的训练知识

**答案：C、D**

### 选项解析

- **A. 调低温度参数**：有帮助，能降低随机性、让输出更稳定，但不能告诉模型“要输出哪些字段、字段名是什么、格式是什么”。属于辅助项，不是结构化提取的关键手段。
    
- **B. 先总结再提取**：看似合理，但有信息损失风险。总结可能压缩或改写姓名、订单号、问题类型等精确字段，且两步操作会引入错误传播。
    
- **C. 明确输出 JSON 格式**：直接约束输出结构，便于程序解析，是结构化提取的核心要求。
    
- **D. 提供期望的 JSON 结构示例**：明确字段名、层级、类型和示例值，显著提升字段抽取的稳定性和一致性。
    
- **E. 完全依赖训练知识**：不可靠，应通过明确指令和示例约束模型。
    

### 知识总结

从邮件中提取结构化数据的关键是：

1. **明确输出格式**：如 JSON；
    
2. **提供 Schema 或示例**：字段名、类型、嵌套结构；
    
3. **必要时再调低 Temperature** 提升稳定性；
    
4. **避免先总结再提取精确字段**，防止订单号等信息丢失。
    

### 解析

标准答案为 **C、D**。A 是锦上添花，B 有信息损失风险，C/D 才直接保证“结构化”。  
记忆：**结构化提取 = 明确格式 + 示例约束；低温只是辅助，总结可能丢信息。**

## 第131题（单选）

**题目：**  
为了降低大模型应用在特定领域产生有害或偏见内容的风险，以下哪种措施属于“预部署”阶段的防护手段？

A. 部署实时内容过滤系统  
B. 对模型的输出进行人工审核  
C. 在模型训练阶段使用经过严格清洗和去偏的数据  
D. 设置用户举报和反馈机制

**答案：C**

### 选项解析

- **A. 实时内容过滤系统**：模型上线服务后的运行时防护，属于部署后阶段。
    
- **B. 输出人工审核**：部署后的运营审核机制。
    
- **C. 训练阶段使用清洗和去偏数据**：发生在模型上线前，属于预部署阶段的数据治理与去偏。
    
- **D. 用户举报和反馈机制**：部署后的持续监控机制。
    

### 知识总结

“预部署阶段”不是指“部署动作开始前的一小段”，而是指**模型上线前整个生命周期阶段**，包括需求设计、数据准备、训练、评估、验证、上线前测试等。

|阶段|典型措施|
|---|---|
|预部署（上线前）|数据清洗去偏、训练对齐、红队测试、上线前评估|
|部署后（运行中）|实时内容过滤、人工审核、举报反馈、监控|

### 解析

模型训练不是“部署”，但属于“部署前”的阶段。题目问的是预部署防护，因此选 **C**。  
记忆：**训练、数据清洗、红队测试 = 预部署；过滤、审核、举报 = 部署后。**

## 第132题（单选）

**题目：**  
为了提高大模型在处理长文档时的效率并降低计算成本，以下哪种方法通常被采用？

A. 要求用户将长文档拆分成多个短段落分别提交  
B. 使用滑动窗口注意力等机制来减少计算复杂度  
C. 增加模型的层数和参数量以提升处理能力  
D. 只处理文档的开头和结尾部分

**答案：B**

### 选项解析

- **A. 用户拆分提交**：会丢失跨段上下文，且增加用户负担，不是通常的模型侧方法。
    
- **B. 滑动窗口注意力等机制**：限制每个 token 只关注局部或部分上下文，降低注意力的计算和显存成本，是长文档处理常用优化。
    
- **C. 增加层数和参数量**：会提高计算成本，不是降本方法。
    
- **D. 只处理开头结尾**：丢失大量信息，不可靠。
    

### 知识总结

标准自注意力复杂度随序列长度呈平方级增长 O(n²)。长文档处理常见优化包括：

- 滑动窗口注意力；
    
- 稀疏注意力；
    
- 分块注意力；
    
- 线性注意力近似；
    
- 层次化注意力。
    

滑动窗口注意力核心：每个 token 只关注左右窗口内邻居，复杂度从 O(n²) 降到约 O(n×w)，近似线性。

### 解析

选 **B**。  
记忆：**长文档降本 = 减少注意力计算复杂度，不是加大模型，也不是只读头尾。**

## 第134题（单选）

**题目：**  
一个智能写作助手在生成新闻稿时，有时会虚构一些不存在的引述或数据。从技术层面看，导致这个问题最可能的原因是？

A. 模型的训练数据中包含了不准确或虚构的信息  
B. 用户的提示词写得不够长  
C. 模型缺乏足够的创造性  
D. 生成长度设置得太短

**答案：A**

### 选项解析

- **A. 训练数据包含不准确或虚构信息**：是幻觉的重要诱因。模型学到这些模式后，可能“仿写”出不存在的引述和数据。在四个选项中相对最接近技术原因。
    
- **B. 提示词不够长**：与虚构事实无直接关系。
    
- **C. 缺乏创造性**：虚构引述不是创造性不足导致，反而常是“过度合理补全”。
    
- **D. 生成长度太短**：长度设置不会导致编造引述或数据。
    

### 知识总结

大模型幻觉的根本机制是：**模型按概率逐 token 生成“看起来合理”的文本，而不是在事实数据库中检索和验证**。  
完整原因包括：

1. 生成机制：概率补全，缺乏事实核查；
    
2. 训练数据：噪声、错误、虚构内容、知识过时；
    
3. 知识截止：不知道最新事实；
    
4. 缺乏外部检索/验证；
    
5. 提示与任务压力：被要求写新闻稿，倾向补全细节；
    
6. 解码策略：采样温度等可能增加编造；
    
7. 对齐问题：模型被训练得“有帮助”，有时宁愿编也不说不知道。
    

### 解析

题目四个选项中 **A 最接近技术原因**。但严格说，幻觉不是单一由训练语料造成，**“概率生成、合理瞎编”是根本机制，训练语料错误是重要诱因**。  
记忆：**幻觉 = 概率生成机制 + 数据噪声/知识不足/缺乏验证；题目选最相关项 A。**

## 第137题（多选）

**题目：**  
以下哪些技术属于参数高效微调方法？

A. LoRA  
B. Prefix Tuning  
C. Prompt Tuning  
D. Adapter  
E. 全参数微调

**答案：A、B、C、D**

### 选项解析

- **A. LoRA**：低秩适配，冻结原模型，只训练低秩矩阵，属于 PEFT。
    
- **B. Prefix Tuning**：训练可学习的前缀向量，作用于每层注意力 K/V，属于 PEFT。
    
- **C. Prompt Tuning**：训练输入端的软提示向量，属于 PEFT。
    
- **D. Adapter**：在 Transformer 层中插入小型适配器模块，只训练适配器，属于 PEFT。
    
- **E. 全参数微调**：更新模型全部参数，不属于参数高效微调。
    

### 知识总结

参数高效微调（PEFT）：冻结大部分预训练参数，只训练少量新增或选择的参数，降低训练和存储成本。

|方法|核心思想|作用位置|参数量|推理开销|
|---|---|---|---|---|
|LoRA|低秩矩阵适配|注意力等线性层|较小|几乎无|
|Prefix Tuning|每层注意力加可训练前缀 K/V|每一层注意力|较小|几乎无|
|Prompt Tuning|输入端加软提示向量|仅输入层|极小|几乎无|
|Adapter|插入小型神经网络模块|Transformer 层内部|中等|会增加|
|全参数微调|更新全部参数|全模型|最大|无额外模块但成本最高|

### 解析

选 **A、B、C、D**。  
记忆：**PEFT 四件套 = LoRA、Prefix、Prompt、Adapter；全参数微调不是 PEFT。**

## 第138题（多选）

**题目：**  
以下哪些技术有助于扩展大模型的上下文处理能力？

A. 滑动窗口注意力  
B. 层次化注意力机制  
C. 知识蒸馏  
D. 线性注意力近似  
E. 模型量化

**答案：A、B、D**

### 选项解析

- **A. 滑动窗口注意力**：每个 token 只关注局部窗口，把注意力复杂度从 O(n²) 降到近似 O(n)，是长上下文常用技术。
    
- **B. 层次化注意力机制**：先处理局部片段，再在更高层整合全局信息，适合长文档/长序列建模。
    
- **C. 知识蒸馏**：主要是把大模型能力迁移到小模型，属于模型压缩/加速，不直接扩展上下文长度。
    
- **D. 线性注意力近似**：用近似方法把注意力复杂度降到线性或近线性，有助于处理更长上下文。
    
- **E. 模型量化**：降低参数精度和显存占用，能间接降低部署成本，但不是扩展上下文处理能力的典型技术。
    

### 知识总结

扩展上下文处理能力的核心方向：

1. **降低注意力复杂度**：滑动窗口、稀疏注意力、线性注意力近似；
    
2. **改进长距离信息建模**：层次化注意力、全局注意力、记忆机制；
    
3. **位置编码外推**：RoPE 插值、NTK 缩放等；
    
4. **分块/检索增强**：分块处理、RAG 等。
    

知识蒸馏和量化主要解决**模型压缩与部署效率**，不是直接扩展上下文。

### 解析

选 **A、B、D**。  
记忆：**长上下文三招 = 局部窗口、层次化、线性近似；蒸馏和量化是压缩部署，不是扩上下文。**

## 第141题（多选）

**题目：**  
在部署大模型服务时，以下哪些措施有助于优化系统性能和成本？

A. 使用模型量化技术减少内存占用和推理延迟  
B. 实现动态批处理以提高 GPU 利用率  
C. 采用持续的预训练来提升模型通用能力  
D. 设置合理的请求超时和重试机制  
E. 使用缓存机制存储频繁请求的响应

**答案：A、B、D、E**

### 选项解析

- **A. 模型量化**：降低内存占用和推理延迟，直接降低部署成本。
    
- **B. 动态批处理**：把多个请求合并推理，提高 GPU 利用率，提升吞吐。
    
- **C. 持续预训练**：主要是提升模型能力，训练成本高，不属于部署服务时的性能/成本优化措施。
    
- **D. 请求超时和重试机制**：避免请求长期占用资源、防止雪崩，提升服务稳定性和资源利用效率。
    
- **E. 缓存频繁请求的响应**：减少重复推理计算，显著降低算力和延迟。
    

### 知识总结

大模型部署优化常见方向：

1. **推理加速**：量化、蒸馏、算子优化、FlashAttention；
    
2. **资源利用**：动态批处理、连续批处理、GPU 调度；
    
3. **减少重复计算**：缓存、语义缓存；
    
4. **服务稳定性**：超时、重试、限流、熔断、降级；
    
5. **成本控制**：按需扩缩容、模型分级路由。
    

持续预训练属于**模型能力建设/训练阶段**，不是部署服务阶段的性能成本优化手段。

### 解析

选 **A、B、D、E**。  
记忆：**部署优化 = 量化 + 批处理 + 缓存 + 超时重试；持续预训练是训练侧，不是部署侧。**
