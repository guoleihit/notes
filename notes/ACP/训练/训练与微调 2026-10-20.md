## 1. 微调时训练损失快速震荡甚至上升，说明模型当前处于？

**题目：**  
在 Qwen2.5-1.5B 模型微调时，训练损失快速震荡甚至开始上升，说明模型当前处于？  
A. 训练成功  
B. 过拟合  
C. 欠拟合  
D. 训练失败

**答案：D 训练失败**

**选项解释：**

- **A 训练成功**：错误。损失震荡上升不是成功表现。
    
- **B 过拟合**：错误。过拟合典型表现是训练损失下降、验证损失上升，而不是训练损失本身快速震荡上升。
    
- **C 欠拟合**：错误。欠拟合是训练损失长期偏高、下降很慢，训练集效果也差，但通常不是“快速震荡并上升”。
    
- **D 训练失败**：正确。快速震荡、损失上升、发散通常说明优化不稳定或训练崩溃，如学习率过大、batch 太小、梯度爆炸、数据异常、混合精度不稳定等。
    

**知识总结：**

- **欠拟合**：训练损失高且降不下去，训练集也学不好。
    
- **过拟合**：训练损失低，验证损失上升，泛化差。
    
- **训练失败/不稳定**：损失震荡、飙升、发散、NaN，优化不可控。
    
- 注意：**短暂小幅震荡不一定失败**；只有持续大幅震荡、损失上升、验证指标恶化，才更明确判定为训练失败。

## 2. 优化检索效果时，哪些方法可以提升大模型对参考信息的查找效率？

**题目：**  
在优化检索效果时，以下哪些方法可以提升大模型对参考信息的查找效率？  
A. 使用结构化的文档格式  
B. 增加模型的训练数据  
C. 减少模型的推理时间  
D. 增加模型的参数数量

**答案：A**

**选项解释：**

- **A 使用结构化的文档格式**：正确。标题、段落、表格、元数据、章节层级等结构化信息有利于切分、索引、检索和引用。
    
- **B 增加模型的训练数据**：不直接提升对已有参考信息的检索效率，主要影响模型知识和泛化能力。
    
- **C 减少模型的推理时间**：提升响应速度，不等同于提升参考信息查找效率。
    
- **D 增加模型的参数数量**：可能提升模型能力，但不直接优化检索过程，且增加成本。
    

**知识总结：**  
提升检索效果常见手段包括：结构化文档、合理切分、元数据、索引、混合检索、重排序等。模型训练数据、参数规模、推理速度不是检索效率的直接优化手段。

## 3. 示例中，哪些是提示词中规定的任务要求？

**题目：**  
在示例中，以下哪些是提示词中规定的任务要求？  
A. 审查文档中有没有错别字  
B. 如果出现了错别字，指出错误并给出解释  
C. “的”和“地”混淆不算错别字  
D. 增加模型的训练数据

**答案：A、B、C**

**选项解释：**

- **A 审查文档中有没有错别字**：属于任务目标。
    
- **B 指出错误并给出解释**：属于输出要求。
    
- **C “的”和“地”混淆不算错别字**：属于判定规则/约束。
    
- **D 增加模型的训练数据**：属于模型训练层面，不是提示词任务要求。
    

**知识总结：**  
提示词中的“任务要求”通常包括：任务目标、处理范围、判定规则、操作步骤、输出内容、输出格式、质量标准、异常处理、禁止事项等。

## 4. 提示词包含哪几部分？任务要求通常包含什么？

**开放题答案：**

提示词常见组成部分：

1. **角色/身份**：如“你是文档审校专家”。
    
2. **任务目标**：要模型做什么。
    
3. **背景/上下文**：业务场景、参考资料、输入说明。
    
4. **任务要求/规则**：判定标准、约束、禁止事项。
    
5. **输入内容**：待处理文档、问题、数据。
    
6. **输出格式**：表格、JSON、列表、分点说明等。
    
7. **示例**：输入输出示例。
    
8. **质量标准**：准确、完整、简洁、引用依据等。
    
9. **异常处理/兜底规则**：信息不足、无法判断时怎么处理。
    
10. **工具/流程说明**：是否先检索、再分析、再输出。
    

简化框架：

> **角色 + 任务 + 背景 + 约束 + 输入 + 输出格式 + 示例**

任务要求通常包含：

> **做什么 + 对什么做 + 按什么规则做 + 输出什么 + 输出成什么样 + 异常怎么办**

**知识总结：**  
不是每个提示词都必须包含全部部分；但任务要求应明确目标、规则、输出格式和异常处理，减少模型自由发挥。

## 5. 推理阶段，哪些因素会影响模型选择下一个输出的 Token？

**题目：**  
在大模型推理阶段，以下哪些因素会影响模型选择下一个输出的 Token？  
A. 候选 Token 的概率  
B. 输入文本的长度  
C. 模型的训练数据  
D. 输出文本的格式

**答案：通常选 A、B、C；严格“直接依据”口径选 A、C，B 有争议。**

**选项解释：**

- **A 候选 Token 的概率**：必选。解码策略直接基于概率分布选择下一个 Token。
    
- **B 输入文本的长度**：有争议。它会通过位置编码、注意力范围、截断、padding、长上下文信息稀释等间接影响概率分布；但“长度”本身不是独立直接输入特征。
    
- **C 模型的训练数据**：间接但确定。训练数据决定模型参数，参数决定推理时的概率分布。
    
- **D 输出文本的格式**：一般不算。除非格式要求写进提示词或作为约束解码规则，否则本身不直接影响下一个 Token 选择。
    

**知识总结：**  
推理时下一个 Token 的分布可概括为：

> **P(next token | 输入上下文，模型参数，解码策略)**

- 训练阶段：训练数据是主要影响因素。
    
- 推理阶段：模型参数固定，**输入上下文是最主要的动态条件**。
    
- 输入内容很重要；输入长度只是输入属性，属于间接影响。
    
- 解码策略包括贪心、采样、温度、top-k、top-p、beam search 等。

## 6. 使用大模型 Agent 时，哪种方式可以增强它的能力？

**题目：**  
在使用大模型 Agent 时，哪种方式可以增强它的能力？  
A. 增加训练数据集  
B. 使用插件  
C. 调整学习率  
D. 集成第三方 API  
E. 更改模型架构

**答案：B、D**

**选项解释：**

- **A 增加训练数据集**：属于重新训练/继续训练，不是“使用 Agent 时”增强能力的方式。
    
- **B 使用插件**：正确。插件可提供搜索、计算、数据库、文件处理等外部工具能力。
    
- **C 调整学习率**：属于训练过程，推理/使用 Agent 阶段通常不涉及。
    
- **D 集成第三方 API**：正确。可调用外部服务获得实时信息、专业能力或执行操作。
    
- **E 更改模型架构**：属于模型设计与训练层面，不是使用 Agent 时增强能力的方式。
    

**知识总结：**  
Agent 的增强主要靠**工具调用、插件、外部 API、检索、记忆、工作流编排**等，而不是在推理使用阶段改训练数据、学习率或模型架构。

## 7. 哪些技术或领域特别适合利用单 Agent 系统的集中处理能力？

**题目：**  
下列哪些技术或领域特别适合利用单 Agent 系统的集中处理能力？  
A. 无人驾驶汽车的路径规划与避障算法  
B. 大型数据中心的资源分配与优化  
C. 单一目标的深度学习训练，如图像分类  
D. 工业自动化中的生产线监控与调度  
E. 数学计算

**答案：按考试口径选 C、D**

**选项解释：**

- **A 无人驾驶路径规划与避障**：不选。安全性、实时性、冗余要求高，单 Agent 有单点失效风险，通常需要多传感器融合、冗余决策甚至多 Agent 协同。
    
- **B 大型数据中心资源分配与优化**：通常排除。大型数据中心规模大、动态性强，更适合分布式/多 Agent 协同优化；单 Agent 集中处理有扩展性和单点瓶颈。
    
- **C 单一目标深度学习训练，如图像分类**：选。目标单一、流程集中，适合单主体集中处理。
    
- **D 工业自动化生产线监控与调度**：选。需要集中监控全局状态、统一调度生产流程，适合单 Agent 集中处理。
    
- **E 数学计算**：通常不选。单 Agent 可以借助工具计算，但不特别体现“集中处理能力”。
    

**知识总结：**  
单 Agent 集中处理适合：

> 目标单一、集中监控、统一调度、规模可控的场景。

不适合：

> 高安全冗余、大规模分布式、强协作、单点失效代价高的场景。

## 8. 个人信息治理过程中，哪些措施可以有效保护用户隐私？

**题目：**  
在个人信息治理的过程中，哪些措施可以有效保护用户的隐私？  
A. 数据去标识化  
B. 用户身份验证  
C. 数据加密  
D. 数据混杂处理  
E. 数据开源处理  
F. 提高模型参数

**答案：A、B、C、D**  
其中 D 按“数据混淆/扰动/脱敏处理”理解。

**选项解释：**

- **A 数据去标识化**：正确。去除或替换可直接/间接识别个人身份的信息。
    
- **B 用户身份验证**：正确。防止未授权访问。
    
- **C 数据加密**：正确。保护存储和传输安全。
    
- **D 数据混杂处理**：若指数据混淆/扰动/加噪声/脱敏，则正确；若只是简单混杂，表述不标准。
    
- **E 数据开源处理**：不选。通常增加隐私暴露风险。
    
- **F 提高模型参数**：不选。与隐私保护无直接关系。
    

**知识总结：**  
隐私保护常见措施：去标识化、匿名化、脱敏、加密、访问控制、身份验证、数据扰动/混淆、差分隐私、最小必要原则等。开源和增大模型参数不是隐私保护措施。

## 9. 哪些因素会影响大语言模型微调的效果？

**题目：**  
下列哪些因素会影响大语言模型微调的效果？  
A. 微调数据的质量和数量  
B. 微调时使用的超参数设置  
C. 预训练模型的选择  
D. 微调持续的轮数 epochs  
E. 是否采用数据增强技术  
F. 计算资源的限制

**答案：A、B、C、D、E、F（全选）**

**选项解释：**

- **A 数据质量和数量**：最关键因素之一，直接影响模型学到什么、是否充分。
    
- **B 超参数设置**：学习率、batch size、权重衰减、LoRA rank 等影响收敛和效果。
    
- **C 预训练模型选择**：基座模型能力、领域匹配度、参数规模决定微调上限。
    
- **D epochs**：太少欠拟合，太多过拟合。
    
- **E 数据增强**：提升数据多样性和泛化能力，小样本微调时影响明显。
    
- **F 计算资源限制**：间接影响模型规模、batch size、训练时长、混合精度/分布式训练等，从而影响效果。
    

**知识总结：**  
微调效果由数据、模型、超参数、训练策略、资源条件共同决定。计算资源虽然不直接改变算法，但会限制可选方案和训练充分程度。

# 今日核心知识总结

1. **微调诊断**
    
    - 欠拟合：训练损失高且降不下去。
        
    - 过拟合：训练损失低，验证损失上升。
        
    - 训练失败/不稳定：损失震荡、飙升、发散、NaN。
        
    - 短暂小幅震荡不一定失败；持续大幅震荡并上升才更明确。
        
2. **检索优化**
    
    - 结构化文档、合理切分、元数据、索引、重排序等可提升检索效率。
        
    - 增加训练数据、参数规模、减少推理时间不是检索效率的直接优化手段。
        
3. **提示词结构**
    
    - 常见：角色、任务、背景、约束、输入、输出格式、示例、异常处理。
        
    - 任务要求 = 做什么 + 对什么做 + 按什么规则做 + 输出什么 + 输出成什么样 + 异常怎么办。
        
4. **推理阶段 Token 选择**
    
    - 直接依据：候选 Token 概率、模型参数、解码策略。
        
    - 输入上下文是推理时最主要的动态条件。
        
    - 输入长度是间接/争议因素；训练数据通过参数间接影响。
        
    - 输出格式除非写入提示词或约束解码，否则不直接影响。
        
5. **Agent 能力增强**
    
    - 使用插件、集成第三方 API、工具调用、检索、记忆、工作流编排。
        
    - 增加训练数据、调学习率、改架构属于训练/设计层面。
        
6. **单 Agent 适用场景**
    
    - 适合：目标单一、集中监控、统一调度、规模可控。
        
    - 不适合：高安全冗余、大规模分布式、强协作、单点失效代价高。
        
7. **隐私保护**
    
    - 去标识化、身份验证、加密、数据混淆/扰动/脱敏、访问控制、差分隐私等。
        
    - 数据开源、提高模型参数不是隐私保护措施。
        
8. **微调效果影响因素**
    
    - 数据质量与数量、超参数、预训练模型、epochs、数据增强、计算资源都会影响。
        
    - 计算资源属于间接影响因素，但确实会影响最终微调效果。
