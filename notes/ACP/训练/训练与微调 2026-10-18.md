## 二、逐题详解

### 第1题：大模型意图分类置信度普遍较低，应该如何处理？

**选项：**

- A. 直接忽略置信度，使用预测结果
    
- B. 放弃使用大模型进行意图分类
    
- C. 重新训练大模型
    
- D. 设置一个置信阈值，低于阈值的结果需要人工审核
    

**答案：D**

**选项解释：**

- **A 错误**：置信度普遍较低说明模型不够确定，直接忽略会放大误判风险。
    
- **B 错误**：过于激进。可以通过阈值、人工审核、二次分类等方式优化。
    
- **C 错误**：重新训练成本高，且不一定能立即解决置信度低的问题。
    
- **D 正确**：设置置信阈值，对低置信度样本进行人工审核或二次处理，是人机协同的稳妥方案。
    

**背后知识：**

- 置信度不等于绝对正确率，可能存在“置信度校准”问题。
    
- 低置信度样本可进入人工审核、规则兜底、小模型复核或主动学习流程。
    
- 实际系统常用“高置信自动通过、低置信人工介入”的策略。

### 第2题：训练循环中，哪段代码用于更新模型权重？

**选项：**

- A. `loss.backward()`
    
- B. `model.train()`
    
- C. `optimizer.step()`
    
- D. `loss = criterion(outputs, labels)`
    

**答案：C**

**选项解释：**

- **A**：反向传播，计算梯度，不直接更新权重。
    
- **B**：将模型切换到训练模式，影响 Dropout、BatchNorm 等行为。
    
- **C**：根据梯度更新模型参数，是权重更新步骤。
    
- **D**：计算损失值。
    

**背后知识：**  
PyTorch 典型训练顺序：

python

optimizer.zero_grad()
outputs = model(inputs)
loss = criterion(outputs, labels)
loss.backward()
optimizer.step()

- `loss.backward()`：算梯度；
    
- `optimizer.step()`：用梯度更新权重；
    
- `optimizer.zero_grad()`：清空上一轮梯度。

### 第3题：微调 Qwen-2.5-1.5B 时发现模型开始欠拟合，可采取的优化措施包括？

**选项：**

- A. 增加训练数据量
    
- B. 增加 `lora_rank` 值
    
- C. 学习率增加一倍
    
- D. 增加训练迭代次数（epoch）
    

**最终复习口径：A、B、D。C 不选。**

**选项解释：**

- **A 有条件正确**：如果欠拟合由数据量不足、数据覆盖不充分导致，增加高质量、多样化数据是合理措施。若训练 loss 很低但验证差，那更偏过拟合，增加数据是缓解过拟合。
    
- **B 正确**：LoRA 的 rank 决定可训练低秩矩阵容量。欠拟合时可适当增大 rank，提高拟合能力。
    
- **C 不选**：欠拟合时可以“适度提高学习率”，但“增加一倍”过于激进，容易导致 loss 震荡、发散或破坏预训练能力。更稳妥的是小步调整、对数尺度搜索、配合 warmup 和梯度裁剪。
    
- **D 正确**：欠拟合可能由训练不充分导致，增加 epoch 是常见措施。
    

**背后知识：**

- **欠拟合**：训练 loss 高、验证 loss 也高，模型连训练数据都没学好。
    
- 常见原因：模型容量不足、训练轮数不够、学习率太小、正则化过强、数据量不足或覆盖不充分。
    
- 学习率调整通常按 `1e-5, 2e-5, 5e-5, 1e-4, 2e-4, 3e-4` 等对数尺度小步搜索，而不是直接翻倍。

### 第4题：构建高质量的数学题微调数据集应包含哪些要素？

**选项：**

- A. 覆盖多种解题思路
    
- B. 统一使用 LaTeX 公式或 Markdown 格式输出公式
    
- C. 大量的数学题解题数据
    
- D. 包含详细分步推导
    

**答案：核心为 A、B、D；C 有条件。**

**选项解释：**

- **A 正确**：数学题常有一题多解，覆盖多种思路能提升模型推理泛化和灵活性。
    
- **B 正确**：统一公式格式有利于训练稳定、解析和评测，减少格式噪声。
    
- **C 有条件**：数据规模重要，但“高质量”不等于“大量”。大量低质、重复数据反而有害。若考试从“数据集构建也需要规模”角度考虑，C 可入选。
    
- **D 正确**：数学微调需要可学习的中间推理过程，不能只有最终答案。
    

**背后知识：**  
高质量数学微调数据通常关注：

1. 题目质量与答案正确性；
    
2. 解题步骤完整、可验证；
    
3. 一题多解与思路多样性；
    
4. 公式格式统一；
    
5. 难度分布和知识点覆盖；
    
6. 数据去重、防泄漏、防错误标注。

### 第5题：在决定模型微调前，应该考虑哪些事情？

**选项：**

- A. 训练服务器资源的成本
    
- B. 训练数据量是否达到微调的最低标准
    
- C. 该任务是否更适合使用 RAG
    
- D. 提示词工程是否能达到预期效果
    

**答案：A、B、C、D**

**选项解释：**

- **A 正确**：微调需要算力、显存、存储、时间和实验迭代成本。
    
- **B 正确**：数据太少或质量差，微调容易欠拟合/过拟合，效果不稳定。
    
- **C 正确**：如果任务主要是注入外部知识、时效信息或私有文档问答，RAG 往往更合适。
    
- **D 正确**：微调成本高，通常应先通过提示词工程、少样本示例验证基础模型能力上限。
    

**背后知识：**  
常见决策顺序：

> 先提示词工程 → 再评估 RAG → 最后考虑微调。  
> 微调适合：任务模式固定、输出风格/格式要求强、需要模型学会特定推理流程，且提示词和 RAG 难以稳定达到效果。

### 第6题：选择 LoRA 秩 r 时需要考虑哪些因素？

**选项：**

- A. 训练数据量
    
- B. 基础模型参数数量
    
- C. 任务复杂度
    
- D. GPU 显存容量
    

**答案：A、B、C、D**

**选项解释：**

- **A 正确**：数据量少时，r 太大会增加过拟合风险；数据多且多样时可适当增大 r。
    
- **B 正确**：基础模型规模会影响相同 r 的相对容量和适配策略。
    
- **C 正确**：简单任务小 r 可能足够；复杂推理、领域知识注入可能需要更大 r。
    
- **D 正确**：r 越大，可训练参数、梯度和优化器状态越多，显存和训练成本越高。
    

**背后知识：**

- LoRA 用低秩矩阵近似参数更新，r 是低秩维度。
    
- r 越大，表达能力越强，但显存、计算和过拟合风险也增加。
    
- 实际调参可从较小 r（如 8、16）开始，根据欠拟合/过拟合表现调整。

### 第7题：关于 Loss function & Cost function，下面描述正确的是？

**选项：**

- A. 用于度量当前所设置的参数是否合适
    
- B. 决定神经元是否被激活并传递信息
    
- C. 帮助寻找函数的参数最优解
    
- D. 拟合任意复杂函数
    

**答案：A、C**

**选项解释：**

- **A 正确**：Loss/Cost 衡量预测与真实值差距，差距越小通常说明参数越合适。
    
- **B 错误**：决定神经元是否激活的是激活函数，如 ReLU、Sigmoid。
    
- **C 正确**：训练通过最小化 Loss/Cost，结合梯度下降等优化算法寻找较优参数。
    
- **D 错误**：拟合任意复杂函数是神经网络的万能近似能力，不是 Loss/Cost 函数的作用。
    

**背后知识：**

- Loss function 通常针对单个样本或一批样本的误差；
    
- Cost function 常指整个训练集上的平均/总代价；
    
- 二者常混用，但核心都是优化目标，指导参数更新。

### 第8题：以下哪两个参数的设置会影响训练时显存占用峰值的大小？

**选项：**

- A. 批量大小 `batch_size`
    
- B. 验证损失计算步数 `evaluation_step`
    
- C. 训练集迭代次数 `epoch`
    
- D. LoRA 的秩 `lora_rank`
    

**答案：A、D**

**选项解释：**

- **A 正确**：batch_size 越大，前向传播激活值、梯度等占用显存越多，是最直接影响因素之一。
    
- **B 不选**：evaluation_step 主要影响验证频率和训练总时长，不直接决定训练显存峰值。
    
- **C 不选**：epoch 影响总步数和总时间，不影响单步训练显存峰值。
    
- **D 正确**：lora_rank 越大，可训练参数、梯度和优化器状态越多，显存开销越大。
    

**背后知识：**  
显存峰值主要来自：

- 模型参数；
    
- 激活值；
    
- 梯度；
    
- 优化器状态；
    
- 临时缓存；
    
- batch size、序列长度、LoRA rank、混合精度策略等。

### 第9题：为了加强大语言模型生成内容的信任机制，哪项措施最具有效果？

**选项：**

- A. 提高模型参数
    
- B. 增加训练轮数
    
- C. 添加 AIGC 声明
    
- D. 优化用户界面
    

**答案：C**

**选项解释：**

- **A 不选**：提高参数可能提升能力，但不直接解决信任机制。
    
- **B 不选**：增加训练轮数可能改善效果，但不等于增强信任。
    
- **C 正确**：添加 AIGC 声明直接提升透明度和用户知情权。
    
- **D 不选**：优化 UI 改善体验，但对内容信任机制作用较弱。
    

**背后知识：**  
AIGC 声明常见形式：

- 显式文字声明：“本内容由 AI 生成，仅供参考”；
    
- 标签/水印；
    
- 元数据标识；
    
- 平台提示；
    
- 高风险场景免责声明。  
    核心是透明度、可追溯性和用户知情权，而不是直接提升模型准确率。

### 第10题：在进行大模型微调项目调研和业务可行性研究阶段，哪个角色对项目成功尤为关键？

**选项：**

- A. 数据工程师，负责数据预处理和清洗
    
- B. 机器学习工程师，专注于模型架构调整和训练
    
- C. 如营销、运营等业务工作者，提供业务领域知识指导数据集构建和评估
    
- D. UI/UX 设计，提升模型输出的交互体验
    

**答案：C**

**选项解释：**

- **A 不选**：数据工程重要，但更偏后续实施。
    
- **B 不选**：模型训练重要，但可行性阶段首先要确认业务价值。
    
- **C 正确**：业务领域专家能提供业务目标、领域知识、数据构建标准、评估口径和风险判断。
    
- **D 不选**：交互体验偏后续产品化阶段。
    

**背后知识：**  
可行性研究阶段最关键的是确认：

1. 项目是否真的解决业务问题；
    
2. 数据能否支撑；
    
3. 评估标准是否合理；
    
4. 成本收益是否成立。  
    没有业务方参与，容易出现“模型训得不错，但业务不可用”。

### 第11题：预训练在自然语言处理大模型中的核心目的是什么？

**选项：**

- A. 利用大量未标注文本数据学习通用的语言结构和模式
    
- B. 直接在特定任务的数据集上进行模型参数优化
    
- C. 通过人类反馈机制不断调整模型输出以更贴合人类偏好
    
- D. 减少模型对大规模计算资源的需求
    

**答案：A**

**选项解释：**

- **A 正确**：通过海量无标注文本自监督学习，掌握通用语言规律、语义和世界知识。
    
- **B 错误**：这是微调/任务特定训练。
    
- **C 错误**：这是 RLHF/人类反馈对齐。
    
- **D 错误**：预训练通常需要大量计算资源，不是减少算力需求。
    

**背后知识：**

- 预训练：学语言和能力，产出基座模型；
    
- 微调：学任务和领域；
    
- 后训练：学对齐人类偏好和安全规范。

### 第12题：在微调大语言模型前的数据准备中，为何需要进行文本分词或标记化处理？

**选项：**

- A. 降低模型训练成本
    
- B. 简化文本内容
    
- C. 帮助模型理解文本结构
    
- D. 提高数据传输效率
    

**答案：C**

**选项解释：**

- **A 不选**：分词会影响序列长度和计算成本，但这是间接效果，不是核心目的。
    
- **B 不选**：分词不是简单“简化内容”，而是转换为模型可处理的 token 表示。
    
- **C 正确**：分词/标记化把文本切分为 token 并映射为 token ID，决定模型看到的文本粒度和序列结构，是模型理解输入的基础。
    
- **D 不选**：不是分词的主要目的。
    

**背后知识：**

- 大语言模型不能直接处理原始字符串；
    
- Tokenization 将文本转为 token 序列，再映射为 ID；
    
- 词表、分词策略、序列长度会影响训练效率、显存和模型效果。

## 三、高频易错点总结

1. **置信度低 ≠ 直接忽略**：应设置阈值、人工审核、二次分类。
    
2. **`loss.backward()` 算梯度，`optimizer.step()` 更新权重**：不要混淆。
    
3. **欠拟合与过拟合要区分**：训练 loss 和验证 loss 都高偏欠拟合；训练低、验证高偏过拟合。
    
4. **学习率不要盲目翻倍**：小步调整、对数搜索、warmup、梯度裁剪。
    
5. **高质量数据 ≠ 单纯大量数据**：质量、多样性、格式统一、分步推导都重要。
    
6. **微调不是首选**：先提示词工程，再评估 RAG，最后考虑微调。
    
7. **LoRA rank 不是越大越好**：要平衡任务复杂度、数据量、显存和过拟合风险。
    
8. **Loss/Cost 是优化目标**：激活函数负责非线性激活，神经网络负责万能近似。
    
9. **显存峰值看单步开销**：batch_size、序列长度、LoRA rank 等直接影响；epoch 影响总时长，不直接影响峰值。
    
10. **信任机制核心是透明度**：AIGC 声明增强知情权和可追溯性。
    
11. **可行性阶段业务方最关键**：先确认业务价值、数据和评估标准。
    
12. **预训练是自监督学通用语言能力**：不是任务微调，也不是 RLHF。
    
13. **分词是模型输入的基础转换**：不是简单简化文本或提高传输效率。
