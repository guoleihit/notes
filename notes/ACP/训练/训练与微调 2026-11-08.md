## 二、逐题解析

### 222. 压测工具 wrk 的关键参数包括？

**选项：**

- A. `-c`（并发连接数）
    
- B. `-d`（持续时间）
    
- C. `-s`（Lua 脚本路径）
    
- D. `-g`（生成报告）
    

**正确答案：A、B、C**

**解析：**

- **A 正确**：`-c` / `--connections` 指定与服务器建立并保持的 TCP 连接总数，即并发连接数。
    
- **B 正确**：`-d` / `--duration` 指定压测持续时间，如 `2s`、`2m`、`2h`，默认 10 秒。
    
- **C 正确**：`-s` / `--script` 用于加载 Lua 脚本，实现自定义请求逻辑，如 POST、自定义 Header、处理响应等。
    
- **D 错误**：wrk 标准参数中**没有 `-g` 生成报告**。测试结束后直接在终端输出报告；详细延迟统计可用 `--latency`，JSON 输出可用 `-j` 或 `--json-format`（视版本/分支而定），但没有 `-g`。
    

**易错点：** 不要把其他压测工具的“报告生成”参数套到 wrk 上。

**扩展：wrk 常见参数**

|参数|作用|
|---|---|
|`-t`|线程数|
|`-c`|并发连接数|
|`-d`|持续时间|
|`-s`|Lua 脚本路径|
|`-H`|添加请求头|
|`--latency`|输出详细延迟统计|
|`--timeout`|请求超时时间|
|`-v`|详细输出|

### 225. 以下哪些技术可与 Multi-Agent 系统结合？

**选项：**

- A. 视觉标注
    
- B. 自然语言处理
    
- C. 机器学习优化
    
- D. 区块链加密
    

**正确答案：A、B、C、D**

**解析：**

- **A 视觉标注**：多智能体可协作完成 3D 标注、自动驾驶数据标注、实例分割数据增强等，如 Tri-MARF、ALGPT、InstaDA。
    
- **B 自然语言处理**：LLM/NLP 为智能体提供理解、生成、通信能力，是多智能体协作的基石，如 GraphMind、DataFactory、LAMP。
    
- **C 机器学习优化**：多智能体强化学习（MARL）用于协同决策与策略优化，如工业调度、结构优化、分布式计算调度。
    
- **D 区块链加密**：用于去中心化多智能体系统的信任、激励、身份与日志不可篡改，如区块链执行层、DID 身份绑定、DAO 治理。
    

**易错点：** 不要认为 Multi-Agent 只和 NLP/强化学习有关；区块链可用于信任与激励层。

**知识点总结：** Multi-Agent 是协作框架，可与感知标注、语言理解、学习优化、信任基础设施结合。

### 226. 以下哪些是 ms-swift 框架的特点？

**选项：**

- A. 支持 350+ LLM 的训练
    
- B. 仅适用于文本生成任务
    
- C. 提供评测和部署功能
    
- D. 开源且易扩展
    

**正确答案：A、C、D**

**解析：**

- **A 正确**：ms-swift 早期明确支持 350+ LLM，后续扩展到 500+、600+，覆盖 Qwen、Llama、InternLM、GLM 等。
    
- **B 错误**：ms-swift 不仅支持纯文本大模型，还支持多模态大模型，可处理图像、视频、语音等，支持 VQA、Caption、OCR、Grounding 等任务。
    
- **C 正确**：提供推理、评测、量化与部署全链路。评测以 EvalScope 为后端，支持 100+ 数据集；部署集成 vLLM、SGLang、LMDeploy，并提供 OpenAI 兼容接口。
    
- **D 正确**：魔搭社区开源框架，插件化设计，可自定义模型、数据集、loss、metric、trainer 等，提供命令行、Web-UI、Python 多种用法。
    

**易错点：** “仅适用于文本生成任务”是典型错误表述。

**扩展：ms-swift 能做什么**

- 支持预训练、指令微调 SFT、DPO/GRPO/KTO/ORPO/SimPO 等对齐算法。
    
- 支持 LoRA、QLoRA、DoRA 等轻量化微调。
    
- 支持 Megatron 并行、GaLore、Flash-Attention 等加速与显存优化。
    
- 支持 AWQ、GPTQ 等量化导出与部署。

### 228. 以下哪些是 vLLM 启动命令的有效参数？

**选项：**

- A. `--port 8000`
    
- B. `--load-format "safetensors"`
    
- C. `--model-name "qwen"`
    
- D. `-gpu-memory 16GB`
    

**正确答案：A、B**

**解析：**

- **A 正确**：`--port` 用于指定 OpenAI 兼容 API 服务器监听端口，默认就是 8000。
    
- **B 正确**：`--load-format` 用于指定权重加载格式，`safetensors` 是合法取值。
    
- **C 错误**：vLLM 指定模型的标准参数是 **`--model`**；自定义 API 中显示名称可用 **`--served-model-name`**。不存在 `--model-name` 启动参数。
    
- **D 错误**：控制 GPU 显存使用的是 **`--gpu-memory-utilization`**，取值为 0~1 的小数（默认 0.9），不是 `16GB` 这种字符串。也不存在 `-gpu-memory` 参数。
    

**易错点：** 混淆 `--model` 与 `--model-name`；混淆显存比例与显存大小。

### 230. 以下哪些是缓解过拟合的措施？

**选项：**

- A. 增大 `lora_dropout`
    
- B. 减少训练轮次
    
- C. 增加训练数据
    
- D. 提高学习率
    

**正确答案：A、B、C**

**解析：**

- **A 正确**：增大 `lora_dropout` 属于正则化，随机丢弃部分 LoRA 路径激活，降低对训练数据的过度依赖。
    
- **B 正确**：减少训练轮次或采用早停，可避免模型过度拟合训练集。
    
- **C 正确**：增加训练数据提升覆盖度和多样性，是最直接有效的缓解过拟合方法之一。
    
- **D 错误**：提高学习率不是缓解过拟合的常规措施，可能导致训练震荡、不收敛甚至发散。缓解过拟合通常考虑降低学习率、加正则化、早停、增加数据等。
    

**易错点：** 不要把“提高学习率”当作万能优化手段；过高学习率更可能导致训练失败。

**扩展：缓解过拟合常见手段**

- 增加数据 / 数据增强
    
- 早停、减少 epoch
    
- L1/L2 正则化、Dropout、增大 dropout
    
- 降低模型复杂度
    
- 使用验证集调参
    
- 标签平滑、权重衰减

### 231. 以下哪些是训练失败的可能原因？

**选项：**

- A. 学习率过高
    
- B. 数据与标签无逻辑关联
    
- C. 训练轮次不足
    
- D. Dropout 率过大
    

**正确答案：A、B、C、D**

**解析：**

- **A 正确**：学习率过高会导致参数更新步长过大，损失震荡、不下降甚至发散，模型难以收敛。
    
- **B 正确**：数据与标签无逻辑关联时，模型无法学到有效映射，损失难以正常下降。
    
- **C 正确**：训练轮次不足导致欠拟合，模型尚未学到有效模式，训练效果不达标。
    
- **D 正确**：Dropout 率过大会过度丢弃信息，导致欠拟合、收敛困难，训练效果显著下降。
    

**易错点：** 本题“训练失败”是广义口径，包含“训练效果不达标”，因此欠拟合类原因也可入选。

### 232. 以下哪种方法属于 PEFT 技术？

**选项：**

- A. 全量微调
    
- B. Adapter Tuning
    
- C. 数据增强
    
- D. 将指定文件夹中的文件加载为 document 对象
    
- E. 将所有 Document 对象合并为一个 Document 对象
    

**正确答案：B**

**解析：**

- **B 正确**：Adapter Tuning 属于 PEFT（参数高效微调）。它冻结预训练模型大部分参数，只插入少量可训练 Adapter 模块，大幅减少训练参数量和显存开销。
    
- **A 错误**：全量微调更新全部参数，不属于 PEFT。
    
- **C 错误**：数据增强是数据处理/扩充手段，不是参数高效微调技术。
    
- **D、E 错误**：文档加载、文档合并属于 LangChain 等框架的数据处理操作，与 PEFT 无关。
    

**易错点：** 看到“微调”就选全量微调；PEFT 的关键是“只训练少量参数”。

**扩展：常见 PEFT 方法**

- LoRA、QLoRA、DoRA
    
- Adapter Tuning
    
- Prefix Tuning、Prompt Tuning、P-Tuning
    
- IA3、BitFit 等

### 234. 在调用 OpenAI 客户端时，以下哪些参数是必须配置的？

**选项：**

- A. `api_key`
    
- B. `base_url`
    
- C. `model_name`
    
- D. `timeout`
    

**正确答案：A、C**

**解析：**

- **A 正确**：`api_key` 是身份验证核心凭证，官方文档标记为必需。也可通过环境变量 `OPENAI_API_KEY` 提供，但逻辑上不可或缺。
    
- **C 正确**：`model_name` / `model` 是发起实际请求时必须指定的参数。不指定模型，请求无法执行。
    
- **B 错误**：`base_url` 有默认值 `https://api.openai.com/v1`，也可通过 `OPENAI_BASE_URL` 环境变量提供。只有连接代理或第三方兼容端点时才需手动指定。
    
- **D 错误**：`timeout` 有默认值，官方 SDK 默认请求超时约 10 分钟（600 秒），通常无需显式配置。
    

**易错点：** 把“有默认值”的参数误认为必须配置；混淆客户端初始化与请求调用两个阶段。

### 235. 在工具函数设计中，以下哪些参数是必需的？

**选项：**

- A. `name`（工具名称）
    
- B. `description`（工具描述）
    
- C. `api_version`（API 版本）
    
- D. `parameters`（输入参数）
    

**正确答案：A、B、D**

**解析：**

- **A 正确**：工具名称是模型调用工具时的唯一标识，必须提供，且通常要求符合命名规范。
    
- **B 正确**：描述用于告诉模型“这个工具做什么、什么时候调用”。清晰的 `description` 是模型正确选择工具的关键依据，实践上应视为必需。
    
- **D 正确**：`parameters` 用 JSON Schema 定义工具入参结构、类型、是否必填。没有参数定义，模型无法正确构造调用参数。
    
- **C 错误**：`api_version` 不是工具函数定义中的通用必需字段，通常属于具体 API 客户端或服务端配置。
    

**易错点：** 把 `api_version` 当成工具 schema 的通用必需字段。

**补充：无参工具也需要 `parameters` 吗？**

- 无参工具**运行时不需要实际参数**，但在工具定义中通常仍需提供一个**空的 `parameters` 对象**，如 `{"type": "object", "properties": {}}`，以显式声明“此工具无参数”。
    
- 在严格规范（如 OpenAI Strict Mode、MCP）中，不能省略 `parameters`；在部分宽松实现中可省略，但实践上推荐显式提供空对象，避免跨平台兼容问题。

### 239. 在深度强化学习中，关于策略梯度（Policy Gradient）方法的描述，下列哪项是不正确的？

**选项：**

- A. 策略梯度直接优化策略而不依赖于值函数
    
- B. 可以处理连续动作空间的问题
    
- C. 通过探索不同的策略来提高性能，但可能导致训练过程不稳定
    
- D. 在高维度动作空间中表现不如基于值函数的方法
    

**正确答案：D（不正确的描述）**

**解析：**

- **A 正确**：策略梯度直接对策略参数进行优化；典型 REINFORCE 不依赖值函数。实际中常引入值函数作为 baseline 或 Actor-Critic，但“直接优化策略”这一核心描述正确。
    
- **B 正确**：策略梯度可以直接输出动作概率或连续动作分布，天然适合连续动作空间。
    
- **C 正确**：策略梯度通常使用随机策略进行探索，但梯度估计方差较大，训练可能不稳定。
    
- **D 错误**：策略梯度方法恰恰在**高维或连续动作空间**中通常比基于值函数的方法更有优势；说它“表现不如基于值函数的方法”是不正确的。
    

**易错点：** 把“策略梯度方差大、不稳定”误推为“高维动作空间不如值函数方法”。不稳定是训练问题，不是动作空间表达能力问题。

**扩展：策略梯度家族**

- 纯策略梯度：REINFORCE。
    
- Actor-Critic：A2C/A3C、PPO、TRPO。
    
- 确定性策略梯度：DDPG、TD3、SAC（SAC 引入熵正则化）。
    
- 与值函数方法区别：策略梯度直接优化策略，天然支持连续/高维动作与随机策略；值函数方法先学 Q 再导出策略，更适合离散动作。

### 240. 在微调过程中，以下哪些情况可能导致过拟合？

**选项：**

- A. 训练数据不足
    
- B. 学习率过高
    
- C. Dropout 率过低
    
- D. 训练轮次过多
    
- E. 硬件资源的限制
    
- F. 文档的质量和数量
    

**正确答案（严格/主流考试口径）：A、C、D**

**解析：**

- **A 正确**：训练数据不足时，模型容易“记住”训练集细节，而非学习泛化规律，是过拟合最典型原因之一。
    
- **B 错误**：学习率过高更容易导致训练震荡、损失不下降甚至发散，属于训练不稳定/失败问题，不是典型过拟合原因。
    
- **C 正确**：Dropout 是正则化手段。Dropout 率过低意味着正则化不足，模型更容易过度依赖训练数据，增加过拟合风险。
    
- **D 正确**：训练轮次过多时，模型会逐渐拟合训练集中的噪声和细节，训练集表现继续提升，但验证集/泛化性能下降。
    
- **E 错误**：硬件资源限制可能影响 batch size、训练速度或能否训练，但不是过拟合的直接机制。
    
- **F 不选（严格口径）**：
    
    - “文档数量不足”与 A“训练数据不足”语义重复。
        
    - “文档质量差”更准确的归因是数据噪声/标注错误，导致模型学偏，属于数据质量问题；严格经典过拟合指“训练集好、验证集差”，质量差不一定表现为该曲线。
        
    - “文档”一词指向模糊：可能指微调语料，也可能指 RAG 知识库文档；若指 RAG 文档，则与微调过拟合无直接关系。
        

**易错点：** 把“学习率过高”当过拟合原因；把“文档质量数量”这种模糊且与 A 重复的选项选入。

**宽口径说明：** 若明确把“文档”定义为微调训练语料，且接受“拟合噪声/不良模式”也算广义过拟合，则 F 可入选。但标准考试中**不选 F 更稳妥**。

**扩展：文档数量/质量如何导致过拟合**

- **数量不足**：模型容量相对过剩，背样本、学虚假相关；训练 loss 很低，验证 loss 先降后升。
    
- **质量差（广义）**：
    
    - 重复文档/模板化 → 模型过度拟合高频模式，训练分布过窄。
        
    - 标注错误/噪声标签 → 模型拟合错误映射，训练集“学会”错误规律。
        
    - 数据分布偏差 → 模型过拟合训练分布，分布外表现差。
        
- 严格说，质量差更偏“数据质量问题导致的泛化失败”，常被宽泛称为“过拟合噪声/不良模式”。

### 3.1 vLLM 常见启动参数分类

|类别|常见参数|说明|
|---|---|---|
|模型加载|`--model`、`--tokenizer`、`--dtype`、`--quantization`、`--trust-remote-code`、`--max-model-len`|`--model` 是核心；`--max-model-len` 遇 OOM 可调小|
|并行性能|`--tensor-parallel-size`、`--pipeline-parallel-size`、`--gpu-memory-utilization`、`--swap-space`、`--enforce-eager`|TP 切分模型到多卡；显存利用率默认 0.9|
|缓存调度|`--enable-prefix-caching`、`--kv-cache-dtype`、`--max-num-seqs`、`--max-num-batched-tokens`|前缀缓存复用相同前缀 KV；fp8 KV Cache 可省约 50% 显存|
|服务接口|`--host`、`--port`、`--api-key`、`--served-model-name`、`--disable-log-stats`|`--port` 默认 8000；`--served-model-name` 自定义 API 显示名|
|LoRA|`--enable-lora`、`--max-loras`、`--max-lora-rank`|动态加载 LoRA 适配器|

**核心调优参数：** `--tensor-parallel-size`、`--gpu-memory-utilization`、`--max-model-len`。

### 3.2 欠拟合 vs 训练失败

|维度|欠拟合|训练失败|
|---|---|---|
|本质|模型没学到有效模式，训练集和验证集都差|训练过程或结果未达预期，范围更广|
|表现|训练损失高、验证损失高、准确率低|损失不降、震荡、发散、NaN、OOM、报错、模型崩溃等|
|原因|模型容量不足、训练轮次不足、正则化过强、Dropout 过大、特征不足|学习率过高、数据/标签错误、数值不稳定、显存不足、配置错误、数据无逻辑关联等|
|解决|增加容量/特征、训练更久、减小正则化、降低 Dropout|先排查数据、超参、数值稳定性、资源与配置，再针对性调整|

**结论：** 欠拟合是训练失败的一种可能原因或表现；训练失败范围更大。231 题采用广义“训练效果不达标”口径，所以“训练轮次不足”“Dropout 率过大”也可作为训练失败原因。

### 3.3 OpenAI 客户端参数分层

|阶段|必需参数|说明|
|---|---|---|
|初始化客户端|`api_key`|唯一明确必需；可通过 `OPENAI_API_KEY` 环境变量隐式提供|
|发起聊天请求|`model`、`messages`|`model` 指定模型，`messages` 是对话依据|
|可选初始化参数|`base_url`、`timeout`、`max_retries`、`organization`、`project`|均有默认值或特定场景使用|
|多组织场景|`organization` / `org_id`|属于多个组织时某些请求需指定|

**易错点：** `base_url` 默认 `https://api.openai.com/v1`；`timeout` 默认约 600 秒；二者非必需。

### 3.4 无参工具与 `parameters` 字段

- **无参工具运行时不需要实际参数**。
    
- 但在工具定义（Schema）中，通常仍需提供**空 `parameters` 对象**：`{"type": "object", "properties": {}}`，以显式声明“无参数”。
    
- 严格规范（OpenAI Strict Mode、MCP）通常要求不能省略 `parameters`；部分宽松实现允许省略，但实践推荐显式提供空对象，保证跨平台兼容。
    
- 同理，`description` 在 schema 层面可能标为 optional，但实践上应视为必需，否则模型容易忽略或误用工具。

### 3.5 策略梯度方法体系

|类型|代表方法|特点|
|---|---|---|
|纯策略梯度|REINFORCE|用整条轨迹回报估计梯度，无偏但方差高|
|Actor-Critic|A2C/A3C、PPO、TRPO|引入 Critic 估计优势函数，降低方差；PPO 工业常用|
|确定性策略梯度|DDPG、TD3、SAC|直接学习确定性策略，适合连续控制；TD3 缓解 Q 过估计；SAC 引入熵正则化|

**与值函数方法对比：**

- 策略梯度直接优化策略，天然支持连续/高维动作和随机策略；基础版本方差大，Actor-Critic 后可显著改善。
    
- 值函数方法先学 Q，再取 max 导出策略，更适合离散动作；连续动作需离散化，面临维度灾难。

### 3.6 文档数量/质量与过拟合（F 选项争议）

**数量不足：**

- 模型容量相对过剩 → 背样本、学虚假相关 → 训练 loss 低、验证差，经典过拟合。
    

**质量差（广义）：**

- 重复模板 → 过拟合高频模式、训练分布过窄。
    
- 噪声标签 → 拟合错误映射，训练集“学会”错误规律。
    
- 分布偏差 → 过拟合训练分布，分布外表现差。
    

**严格口径：** 质量差更偏“数据质量问题导致的泛化失败”，不必然表现为经典“训练集好、验证集差”；且“数量不足”与 A 重复。因此标准考试中 **240 题不选 F 更稳妥**。

## 四、知识点总结

1. **wrk**：关键参数 `-t/-c/-d/-s/-H/--latency`；无 `-g` 生成报告。
    
2. **Multi-Agent**：可与视觉标注、NLP、机器学习优化、区块链加密结合；区块链用于信任、激励、身份、日志。
    
3. **ms-swift**：一站式大模型与多模态微调部署框架；支持 600+ 文本 LLM、400+ 多模态模型；支持 SFT、DPO/GRPO、LoRA/QLoRA、评测、量化、部署；开源插件化，非仅文本生成。
    
4. **vLLM**：`--model` 指定模型；`--served-model-name` 自定义 API 名；显存用 `--gpu-memory-utilization`（0~1）；`--port` 默认 8000；`--load-format safetensors` 合法。
    
5. **过拟合/欠拟合/训练失败**：
    
    - 缓解过拟合：增大 dropout、减少轮次/早停、增加数据、正则化。
        
    - 提高学习率不缓解过拟合，易导致训练失败。
        
    - 训练失败广义包括：学习率过高、数据标签无逻辑关联、训练轮次不足、Dropout 过大、OOM、数值不稳定等。
        
    - 欠拟合关注“没学会”；训练失败关注“未达预期”。
        
6. **PEFT**：冻结大部分参数，只训练少量参数；Adapter Tuning、LoRA、QLoRA、Prefix/Prompt/P-Tuning、IA3、BitFit；全量微调不是 PEFT。
    
7. **OpenAI 客户端**：初始化 `api_key` 必需；请求 `model`、`messages` 必需；`base_url`、`timeout` 有默认值。
    
8. **工具函数设计**：`name` 必需；`description`、`parameters` 实践必需；`api_version` 非通用必需。无参工具需空 `parameters` 对象显式声明。
    
9. **策略梯度**：直接优化策略；适合连续/高维动作；可学随机策略；基础版本方差大、不稳定；高维动作空间通常优于值函数方法。

## 五、易错点速记

1. **wrk 没有 `-g` 生成报告参数。**
    
2. **Multi-Agent 可与区块链结合**，用于去中心化信任与激励。
    
3. **ms-swift 不是仅文本生成**，支持多模态。
    
4. **vLLM 没有 `--model-name`**，用 `--model` 或 `--served-model-name`；显存用比例参数。
    
5. **提高学习率不缓解过拟合**。
    
6. **训练轮次不足、Dropout 过大属于广义训练失败原因**。
    
7. **PEFT 不是全量微调**，Adapter Tuning 是 PEFT。
    
8. **OpenAI 的 `base_url`、`timeout` 有默认值，不是必须配置**；`api_key` 和请求时的 `model`/`messages` 才是关键必需项。
    
9. **工具函数设计中 `api_version` 非通用必需**；无参工具也要空 `parameters` 定义。
    
10. **策略梯度在高维/连续动作空间通常更有优势**，D 项说“不如值函数方法”是错误的。
    
11. **240 题 F 选项模糊**：“数量不足”与 A 重复，“质量差”属广义过拟合/数据问题；严格考试不选 F。
