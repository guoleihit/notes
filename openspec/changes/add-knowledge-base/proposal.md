## Why

建立一个个人学习知识库：存放学习笔记，便于查找和继续学习。核心痛点有二——过去的笔记因工具/云服务而丢失（因此数据所有权是硬约束）；传统分类式组织成本过高，检索依赖手动维护的索引。

方案采用"关键词检索 + 大模型问答"（grep RAG）：不引入 embedding 与向量索引，避免额外 API 成本与本地高配置要求，检索层用 grep 关键词匹配，生成层复用现有的 OpenCode Go 订阅（GLM 聊天模型）回答问题。

## What Changes

- 新增**笔记存储**能力：所有笔记以纯文本 Markdown 存放在本地，用 git 版本化，通过良好的目录分类组织，支持增量添加与修改已有内容（数据永不丢失，工具可替换）。
- 新增**关键词检索**能力：用 grep 关键词匹配在 `notes/` 下查找命中的笔记与片段，透明、实时、免维护索引。
- 新增**问答**能力：将关键词命中的候选文档与用户问题一起交给大模型，由大模型返回答案。
- 新增**知识库整理**能力：`kb lint` 按需整理知识库，发现可关联但未链接的笔记、孤立笔记等，增量处理并记录档案。
- 新增**草稿与发布**能力：用 `drafts/` 草稿区暂存未完成的灵感（不参与检索），`kb publish` 将草稿发布为 `notes/` 下的正式笔记。

## Capabilities

### New Capabilities
- `note-storage`: 纯文本 Markdown 笔记的存储、增量添加、内容修改与 git 版本化，以目录分类组织。
- `keyword-search`: 基于 grep 关键词匹配的笔记检索。
- `llm-answer`: 将检索命中的候选文档与问题交给大模型生成答案。
- `knowledge-lint`: 按需整理知识库，发现关联与问题，增量处理并记录档案。
- `draft-publish`: 草稿区隔离与草稿发布，将未完成的灵感转为正式笔记。

### Modified Capabilities

（无——本项目为新建，无既有能力。）

## Impact

- 新增依赖：OpenAI 兼容的 LLM 客户端（指向 OpenCode Go 的 GLM 端点）。
- 检索层无索引、无向量存储，无需 embedding 服务。
- 不影响任何既有代码（当前仓库为空，仅含 OpenSpec 脚手架与已废弃的 embedding 原型代码）。
